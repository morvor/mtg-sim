# mtg-sim

A rules engine for Magic: The Gathering, written in Rust, for running simulations. It
has no user interface: games are played by agents (programs that answer the engine's
decisions), and the engine enforces the rules.

The engine follows the Comprehensive Rules (`data/comprehensive-rules.txt`, effective
2026-09-25) and compiles card behavior from Scryfall's Oracle text. It is checked against
both sources:

- **Comprehensive Rules**: each rule is cited by a test that exercises it
  (`cr!("704.5a")`), or listed in `docs/cr-exemptions/` with the reason it has no
  behavior to test (for example, rules about the physical card).
- **Scryfall rulings**: a test that checks a ruling cites it (`ruling!("Card", "text")`),
  or the ruling is listed in `docs/rulings-exemptions/` with a reason. Both macros fail
  the test if the rule or ruling doesn't exist, so citations can't be made up.
- **Cards**: the Oracle compiler reports every ability text it can't compile, so a card
  is either fully supported or reported as unsupported along with that text.

The coverage tools list what is neither cited nor exempt.

Current numbers are in `docs/CR_COVERAGE.md`, `docs/CARD_COVERAGE.md` and
`docs/RULINGS_COVERAGE.md`, generated by `mtg-tools` (below).

## Quick start

```sh
cargo build --release
cargo test --workspace                                        # the full test suite
cargo run --release -p mtg-sim -- --games 200                 # simulate games
cargo run --release -p mtg-sim -- --deck a.txt --deck b.txt   # "4 Lightning Bolt" lines
cargo run --release -p mtg-sim -- --random-decks --games 1000 # fuzz the engine
cargo run --release -p mtg-sim -- --every-card --threads 4     # play every supported card
```

`--random-decks` gives every game new random decks of fully supported cards. It reports
any panic, any hang, and any rules violation its checks find (a player getting priority
while a state-based action is pending, CR 117.5; zone lists that don't match their
objects; out-of-date characteristics; mana or spells left as a step ends; damage left as
a turn begins or marked on a noncreature; life totals and counters that don't add up to
the events), each with a command that replays that game (`--only G --log`).

`--every-card` plays games built around each fully supported card in turn (both decks
hold copies of it, in the variant it needs), with the same checks, and reports which
cards were never cast and which of their abilities were never activated or triggered,
grouped by likely reason (`--from N --count M`, `--filter TEXT`, `--kind KIND`,
`--games-per-card K`, `--report FILE`). See [docs/EVERY_CARD.md](docs/EVERY_CARD.md)
for the latest full sweep.

## Data

| File | Source |
|---|---|
| `data/comprehensive-rules.txt` | The Comprehensive Rules text file from Wizards of the Coast |
| `data/oracle_cards.jsonl.gz` | Scryfall bulk data, type `oracle_cards`, one card object per line |
| `data/rulings.jsonl.gz` | Scryfall bulk data, type `rulings`, one ruling per line |
| `data/oracle_tags.jsonl.gz` | Scryfall Tagger oracle tags, one tag per line |

`data/manifest.json` and `data/rules-manifest.json` record where and when each file was
fetched. To update, download the bulk files listed at
<https://api.scryfall.com/bulk-data>, convert each JSON array to JSON Lines, gzip it, and
replace the file. Then run the test suite and the coverage tools: new rules text or new
Oracle wording shows up as failing citations and unsupported abilities.

## Layout

| Crate | What |
|---|---|
| `crates/mtg-data` | Loads the data files; parses the Comprehensive Rules; defines the `cr!` and `ruling!` citation macros |
| `crates/mtg-engine` | The engine |
| `crates/mtg-sim` | Command-line simulator and fuzzer |
| `crates/mtg-tools` | Coverage reports: `cr-coverage`, `card-coverage`, `rulings-coverage`, `unsupported` |

Inside the engine:

- `oracle/` compiles Oracle text into the ability language (`ability.rs`), a data
  structure of effects, costs, triggers, static abilities and replacement effects. Text
  patterns are registered in `oracle/patterns/`, one file per topic.
- `game.rs` holds the game state. Every zone change creates a new object (CR 400.7); the
  old one remains as last known information.
- `layers.rs` computes characteristics through the seven layers with timestamps and
  dependencies (CR 613). `replacement.rs` applies replacement and prevention effects
  (CR 614-616). `triggers.rs` detects triggered abilities from events (CR 603).
  `sba.rs` performs state-based actions (CR 704). `stack.rs`, `casting.rs`, `mana.rs`
  and `combat.rs` cover the stack, casting and activating, mana, and combat.
- `kw/` implements keyword abilities (CR 702), one file per keyword; `kwa/` implements
  keyword actions (CR 701).
- `multiplayer/`, `casual.rs`, `commander_rules.rs`, `planechase.rs`, `draft.rs` and
  others cover multiplayer rules and variants (CR 800-905).

`CLAUDE.md` has the full map of the engine and the conventions for extending it.

## Playing games from code

`crates/mtg-engine/examples/play_a_game.rs`
(`cargo run --release -p mtg-engine --example play_a_game`):

```rust
let red = deck(&[(24, "Mountain"), (20, "Lightning Bolt"), (16, "Raging Goblin")]);
let green = deck(&[(24, "Forest"), (20, "Grizzly Bears"), (16, "Giant Growth")]);
let agents: Vec<Box<dyn Agent>> = vec![
    Box::new(RandomAgent::new(1)),
    Box::new(RandomAgent::new(2)),
];
let mut game = Game::new(GameConfig { seed: 7, ..Default::default() }, vec![red, green], agents);
game.logging = true;
let result = game.run(); // GameResult::Win(players) or GameResult::Draw
```

An agent implements `Agent::decide(&mut self, game: &Game, player: PlayerId, decision:
&Decision) -> Answer`. The engine validates every answer and falls back to a legal default
for an invalid one. `Game` is `Clone`, and `Game::set_agents` replaces the agents on a
copy, so a search-based agent can play ahead on copies of the game.

## Tests

Tests live in `crates/mtg-engine/tests/`, one binary per directory:

- `cr/`: rules tests, named after the rule (`r704_state_based_actions.rs`).
- `keywords/`: keyword abilities (`k702_019_trample.rs`).
- `actions/`: keyword actions (`a701_034_proliferate.rs`).
- `rulings/`: Scryfall rulings, grouped by mechanic or card.
- `cards/`: card behavior.

Every rules test starts with `cr!("704.5a", ...)`, naming the rules it verifies, and a
test that encodes a ruling cites it with `ruling!("Card Name", "distinctive text")`.
Tests use `mtg_engine::testing::TestGame`, which sets up a game state directly and answers
decisions from a script.

```sh
cargo run --release -p mtg-tools -- cr-coverage                          # uncited, unexempt rules
cargo run --release -p mtg-tools -- card-coverage                        # supported cards by format
cargo run --release -p mtg-tools -- rulings-coverage --card "Tarmogoyf"  # one card's rulings
cargo run --release -p mtg-tools -- unsupported --limit 50               # most common unsupported texts
```
