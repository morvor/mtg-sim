## Regenerating

Regenerate the tier file and this report before each milestone, and after a new card set or a CR update (other work changes round trips and structure coverage all the time, so the numbers drift between regenerations; a card newer than the tier file counts as at most compiled, and a card that stops compiling or round-tripping drops at once). Run nothing else heavy alongside the sweep:

```sh
export CARGO_BUILD_JOBS=2
rm -rf target/structlog
MTG_STRUCTURE_LOG=$PWD/target/structlog cargo test --workspace          # structure log
# The every-card sweep: about 2.3 hours with 3 threads, so three chunks of ~46 min each
cargo run --release -p mtg-sim -- --every-card --threads 3 --from 0 --count 10100 --report target/every-card-0.tsv
cargo run --release -p mtg-sim -- --every-card --threads 3 --from 10100 --count 10100 --report target/every-card-1.tsv
cargo run --release -p mtg-sim -- --every-card --threads 3 --from 20200 --count 10100 --report target/every-card-2.tsv
cat target/every-card-[012].tsv > target/every-card.tsv
cargo run --release -p mtg-tools -- roundtrip --write docs/ROUNDTRIP.md     # if round trips changed
cargo run --release -p mtg-tools -- verified --logs target/structlog --report target/every-card.tsv --write
cargo run --release -p mtg-tools -- card-coverage --write docs/CARD_COVERAGE.md
```

Each chunk is a separate command because one run of the whole sweep takes longer than a command may run here (a pool larger than 30,300 cards needs a fourth chunk). `verified` reads the concatenated reports' `outcome` lines (whether each card was cast, and its failed games) and `failure` lines (a card a failed game's message names as an object, like a rules-check violation's, isn't fuzz-clean either).

`mtg-tools verified --card "Name"` prints one card's tier and failed checks.
