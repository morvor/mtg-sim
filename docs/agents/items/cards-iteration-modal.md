# cards-iteration-modal: Iteration and structure: "for each [player/object], [instruction]", "starting with ...", modal headers, multi-line blocks (levels, Seasons, chapters), repeat loops, flavor words — 325 texts / 322 cards (286 unlocked alone)

SCOPE: 325 unsupported ability texts (325 on paper cards) blocking 322 paper cards; 286 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-iteration-modal.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: "For each opponent/player, [instruction with 'that player' / 'up to one target creature that player controls']" (Hideous Taskmaster, Riptide Gearhulk), "For each [object] [qualifier], [instruction about it/its controller]" ("For each creature destroyed this way, its controller creates ...", "For each creature attacking you, create a token that's a copy of that creature and that's blocking that creature", "For each kind of counter on target permanent, ...", "For each color, put a +1/+1 counter on a Dragon you control of that color"), sequential choices ("Starting with you, each player chooses up to one permanent ...", "Starting with the next opponent in turn order, ..."), modal headers ("Choose one. If it was kicked, choose both instead", "choose one at random. If you discarded a card this turn, you choose one instead", "choose up to X, where X is ...", "As ~ enters, choose Khans or Dragons" with following bullet abilities), multi-line blocks (level-up striations with abilities, Season "{P}" pawprint modes, Saga chapter lines whose wrapper fails), repeat loops ("repeat this process", "Then repeat this process for instant cards with mana values 3 and 4"), and long flavor words / short-name normalization ("A Thousand Souls Die Every Day — {T}, Sacrifice ...", "Put a +1/+1 counter on King Darien").

APPROACH: 1. "For each X, [effect]" → `Effect::ForEach`/`ForEachPlayer` with the loop variable bound as the referent for "that player", "it", "its controller", "that creature" inside; targets inside the loop ("up to one target creature that player controls") are chosen per iteration at cast/activation (CR 601.2c with per-player target sets).
2. "Starting with [player], each player [chooses]" → ordered ForEachPlayer (APNAP-like order from the given player).
3. Modal headers: extend `ModalHeaderPattern`s for conditional mode counts, random modes, value-defined maxima, and the "As ~ enters, choose A or B" + "• A — ability" structure (Sieges/Frontier Siege-style linked choices).
4. Blocks: fix `group_blocks` patterns for remaining level-up/pawprint layouts; chapter lines should only fail when their effect fails (those belong elsewhere).
5. Normalizer: allow long flavor words before any ability when followed by a full ability; extend legendary short names ("King Darien").

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
