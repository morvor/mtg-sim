### Question 1: "if it's the first time [the trigger event] this turn" on resolution

**The question.** CR 603.4 checks an intervening "if" again as the ability resolves. Botanical Brawler, Stalwart Successor and Captain America, Living Legend condition their abilities on the trigger event being the first of its kind this turn; Vengevine, Alania and Codespell Cleric on the triggering (or the source's own) spell being the Nth spell of a kind cast this turn. If another event of the kind happens while the ability waits (a second counter put on the permanent, the creature untapped and tapped again, another spell cast in response), is the condition still true as the ability resolves?

**Survey of the wordings** (`data/oracle_cards.jsonl.gz`, scripts in the investigator's scratchpad; every card whose Oracle text says "first/second/third ... time", "for the first time", "the Nth spell ... this turn", or an intervening "if" with an ordinal or "only"/"no other"/"another" about this turn):

Brawler, Captain America: counted again as it resolves (`== 1`). Now all three: about the trigger event |

**Sources** (verbatim; from `data/` unless stated).
- **CR** (effective 2026-09-25):
  - 603.4: "A triggered ability may read “When/Whenever/At [trigger event], if [condition], [effect].” When the trigger event occurs, the ability checks whether the stated condition is true. The ability triggers only if it is; otherwise it does nothing. If the ability triggers, it checks the stated condition again as it resolves. If the condition isn’t true at that time, the ability is removed from the stack and does nothing. Note that this mirrors the check for legal targets. This rule is referred to as the “intervening ‘if’ clause” rule. (The word “if” has only its normal English meaning anywhere else in the text of a card; this rule only applies to an “if” that immediately follows a trigger condition.)" Its example rechecks a state: "Felidar Sovereign reads, “At the beginning of your upkeep, if you have 40 or more life, you win the game.” ... As the ability resolves, that player’s life total is checked again. ..." The recheck is in every archived CR (https://github.com/pit142857/mtg-cr, commit 8351b94f) from the one dated 1999-11-01 on ("On resolution, the ability rechecks the condition.", 404.3 by the one dated 2001-07-23); 603.4's present words since the one dated 2009-07-08. No change since bears on the question.
  - 608.2a: "If a triggered ability has an intervening “if” clause, it checks whether the clause’s condition is true. If it isn’t, the ability is removed from the stack and does nothing. Otherwise, it continues to resolve. See rule 603.4."
  - 603.2: "Whenever a game event or game state matches a triggered ability’s trigger event, that ability automatically triggers. The ability doesn’t do anything at this point." 603.2c: "An ability triggers only once each time its trigger event occurs. However, it can trigger repeatedly if one event contains multiple occurrences."
  - 608.2i: "Some effects look back in time and require information about previous game states and actions rather than considering the current game state. If such an effect requires information from the game about an object or group of objects, and that effect is not taking any actions on those objects, they don’t need to be currently in the zone they were in at the time of that previous game state or action, nor do they need to currently meet the criteria described in the action, as long as they did so at the specified time. This is an exception to 608.2h."
  - 700.1: "Anything that happens in a game is an event. ... The text of triggered abilities and replacement effects defines the event they’re looking for. ..."
  - 700.14 (context: the CR's one definition of an ordinal trigger event fixes it at the event): "Some abilities trigger “Whenever you expend N.” A player expends N if they pay a cost to cast a spell and the amount of mana that player spent this turn to cast spells prior to paying that cost was less than N and became at least N after paying that cost."

- **Rulings on intervening "if" clauses about the trigger event:** Mighty Servant of Leuk-o ("Whenever this Vehicle becomes crewed for the first time each turn, if it was crewed by exactly two creatures, ..."; 2022-06-10): "An ability that triggers whenever a Vehicle "becomes crewed" triggers when its crew ability resolves. For example, if you cast a spell, then respond to the triggered ability with a second spell, you'll gain 4 life total." A "this turn" count in the effect is taken as the ability resolves, spells cast in response included; it isn't about the trigger event.

**Readings.**
- **R1, about the trigger event (now the engine's throughout).** "It" in "if it's the first time ..." is the event that made the ability trigger (in Vengevine's, the triggering spell). Rechecking "the stated condition" (603.4) asks again whether that event was the first of its kind this turn, and it still was: what happened before it can't change. Counted as the ability resolves, only this turn's events up to the trigger event and those simultaneous with it count.
- **R2, a recount (the engine's for Botanical Brawler and Captain America).** "It's the first time ..." read as "it has happened exactly once this turn", a state of the game rechecked like 603.4's life total: a second event of the kind makes it false. Read the same way, Vengevine's "it's the second creature spell you cast this turn" would be false once a third is cast, against any reading of "it" as the triggering spell, and Alania's and Codespell Cleric's likewise.
- **For R1:** the pronoun; the spell ordinals, whose "it" can only be the spell; Mighty Servant of Leuk-o's and Tunnel Ignus's rulings evaluating an intervening "if" about the trigger event against that event; Vengevine's release notes listing what must still hold as the ability resolves (Vengevine in the graveyard) and not the count; 700.14 fixing the CR's one ordinal trigger event at the moment of the event; and consistency (Stalwart Successor and the spell ordinals already read this way).
- **For R2:** 603.4's recheck "at that time" and its state example; Aetherflux Reservoir's resolution-time count (an amount in the effect, not about the trigger event).

**Ruled out.**
- **Not A:** no two sources conflict; the question is a gap in them.
- **Not B:** no dated change bears on it (the recheck is in every archived CR since 1999; all the cards are from 2010 on).
- **Not C:** no ruling decides it: none speaks of an event of the kind happening while such an ability waits, and the cards most exposed (Stalwart Successor, Captain America) have no rulings.

**Engine: changed (Botanical Brawler and Captain America), unchanged elsewhere.**
- **Before** (confirmed with a scratch test, Nov 19, not committed): Botanical Brawler with a second +1/+1 counter put on the Bears while its ability waited: its ability did nothing (Brawler stayed at 2 counters); Captain America with the Bears untapped and tapped again in response: the Bears stayed tapped; Stalwart Successor in the same spot: still put its counter (3 on the Bears). Brawler's and Captain America's conditions were `Compare(EventsThisTurn(..), Eq, 1)` counted again as they resolved.
- **After:** both untap/put the counter. The conditions are `Value::EventsDuring(HistoryWindow::ThisTurnUntilTriggered, ..)`: as the ability triggers, this turn's events so far (as `EventsThisTurn` counts them, the rest of the trigger event's simultaneous batch included); as it resolves, only the first `EventInfo::turn_events_seen` of this turn's events, the number recorded when the ability triggered (`Game::seen_as_triggered`, stamped where `detect_triggers` and `check_batch_triggers` create the pending triggers). A copy of the triggered ability keeps it with the trigger event. Pending triggers created elsewhere (delayed, keyword-specific) have no stamp and count this turn's events so far (no such card has an "it's the first time" condition).
- **Code:** `ability.rs` (`HistoryWindow::ThisTurnUntilTriggered`), `object.rs` (`EventInfo::turn_events_seen`), `triggers.rs` (`seen_as_triggered`), `kw/value_results.rs` (`events_until_triggered`, `event_objects_until_triggered`, `turn_events_indexed` with a limit), `history_query.rs` (`events_during`, `objects_during`, `window_events`), `oracle/patterns/history_conditions.rs` (`nth_time_counters`; `window_suffix`), `oracle/patterns/history_conditions_4.rs` (`first_time_referent`), `oracle/render/events_happened.rs` (`window_phrase`, `happened`: the window reads "this turn"). Botanical Brawler and Captain America still pass the Oracle round trip (checked with `oracle::render::compare::check_card`); Stalwart Successor's failure (its trigger form renders "for the first time each turn") is unchanged.
- **Unchanged:** Stalwart Successor (`first_time_counters`: the condition is part of its trigger, checked only as it triggers, which gives R1's answer; its counters of several kinds put at once are one time, which a per-event count wouldn't give); the spell ordinals (`CAST_BY_THEN`); conditions not about the trigger event (Nightpack Ambusher's "if you didn't cast a spell this turn" sees a spell cast in response).

**Remaining gaps.**
- The engine still represents Stalwart Successor's condition as part of its trigger, so it fails the Oracle round trip (pre-existing). Rewriting it as an intervening "if" needs a count of "times" that treats counters of several kinds put at once as one time (CR 122.6's "one or more counters" batches), which `Tally::Events` doesn't.

### Question 2: the order of simultaneous "as enters" replacement effects
