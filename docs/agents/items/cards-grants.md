# cards-grants: Ability-granting grammar: quoted abilities on objects/tokens, conditional and group keyword grants — 273 texts / 273 cards (241 unlocked alone)

SCOPE: 273 unsupported ability texts (273 on paper cards) blocking 273 paper cards; 241 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-grants.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: "[object] gains/has [keyword list] and "[quoted ability]" [duration] [condition]" everywhere: tokens with quoted abilities ("create a 1/1 red Devil creature token with "When this token dies, it deals 1 damage to any target."", "create X 1/1 black Rat creature tokens with "This token can't block.""), granted triggered/activated abilities with self-references meaning the recipient ("It gains haste and "At the beginning of the end step, sacrifice this creature.""), objects becoming types with abilities ("It's a Treasure artifact with "{T}, Sacrifice this artifact: Add one mana of any color," and it loses all other card types", "Clues you control are Equipment ... and have "Equipped creature gets +1/+1" and equip {2}"), conditional grants ("has menace as long as you sacrificed a permanent this turn", "has haste and ward {2} as long as it was cast"), group grants with complex subjects ("Players gain hexproof until end of turn", "Eldrazi you control have "{T}: Add one mana of any color.""). Also "enters with ... and with "[ability]"" (kicker volvers).

APPROACH: 1. Quoted abilities: compile the quoted text with `oracle::parse_ability` in a context where "~"/"this creature/token" mean the object that has the ability (oracle/mod.rs raw_text() exists for this distinction) and attach as `Modification::AddAbility` (or the token's abilities). Many failures are the wrapper ("with "..."" after a token description, a list mixing keywords and quotes, the "and" before a quote) rather than the quoted text.
2. Keyword lists with quotes: extend `keywords::split_keyword_phrases`/`effects::keyword_mods` to accept quoted abilities and keyword-with-cost items ("ward {2}", "equip {2}").
3. Conditional statics: "[static] as long as [condition]" trailing form (leading form exists in statics.rs).

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
