# structure-coverage: Structure coverage: group abilities by compiled structure and report structures no test exercises

WHY: cards whose abilities compile to the same structure (differing only in numbers, names, mana amounts) run identical engine code, so one test covers all of them; cards with a structure no test has exercised are unverified. This tool measures that, so test work goes where it's needed.

1. Fingerprint: for every compiled ability of every supported card, a structural fingerprint of its AST with literal parameters abstracted (numbers and X values, mana amounts within a cost, P/T values, the card's own name, counts) but every semantic choice kept (filters and their qualifiers, zones, players, targets, durations, conditions, types, keywords, triggers, replacement shape, modes). Put it next to the AST (e.g. ability.rs helper or a new module) so it stays in sync when variants are added (match exhaustively; no catch-alls).
2. Exercised: instrument the engine so that, when an environment variable (e.g. MTG_STRUCTURE_LOG=<dir>) is set, every ability that is actually activated, triggered, resolved, or applied as a static/replacement effect in a game records its fingerprint (and card name). Test binaries run in parallel threads and processes, so write per-process files (or lock); the cost must be zero when the variable is unset. Abilities only checked for legality don't count.
3. Tool: `mtg-tools structure-coverage [--write docs/STRUCTURE_COVERAGE.md] [--limit N]`: runs from collected logs (document the command sequence: e.g. `MTG_STRUCTURE_LOG=target/structlog cargo test --workspace` then the tool): number of distinct structures, how many are exercised by some test, and the unexercised ones ranked by the number of cards that share them, each with example cards and their ability text. Also per-card: a card is 'structure-verified' when every one of its abilities' structures is exercised.
4. Seed: write tests for the top 30-50 unexercised structures by card count (real cards through TestGame, asserting the ability's in-game outcome matches its text, citing cr!/ruling! where relevant), and report the numbers before and after.
5. Tests for the fingerprint itself: two cards that differ only in a number share a fingerprint; cards differing in a qualifier ('nontoken', 'you control', 'until end of turn', 'up to') do not.

DONE when the tool reports structure coverage for all supported cards, docs/STRUCTURE_COVERAGE.md records it, and the seed tests have landed.
