# cards-replacements: Replacement and prevention grammar ("if ... would ..., instead", "the next time ... would", prevention/redirection, ETB replacements "as ~ enters", "enter as a copy") — 388 texts / 406 cards (318 unlocked alone)

SCOPE: 388 unsupported ability texts (388 on paper cards) blocking 406 paper cards; 318 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-replacements.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Compile replacement effects as EVENT PATTERN + REPLACEMENT: event patterns ("you would draw a card", "a player would draw a card except the first one they draw in each of their draw steps", "damage would be dealt to ~ while it has a +1/+1 counter on it", "a nontoken creature would die", "one or more +1/+1 counters would be put on a permanent you control", "you would proliferate", "a creature would enter under an opponent's control this turn", "a source would deal 3 or more damage to a permanent or player"), scopes ("the next time ... this turn", "the next N damage", "until end of turn"), and replacements (instead [instructions], prevent, redirect "is dealt to ... instead", "that many plus one", "twice", "enters with/under/as"). ETB replacements: "As ~ enters, choose a [type/name/color/player/opponent]", "You may have ~ enter as a copy of [filter], except [modifications]", "enters with X +1/+1 counters, where X is ...", "If its mana cost contains {X}, it enters with ...".

PHRASE FAMILIES (texts in family; representative failing pieces and cards):

APPROACH: 1. One event-pattern parser producing `ReplacementEvent` (extend variants generically: draw with exceptions, damage with source/target filters and amount thresholds, counters placed with filters, keyword actions like proliferate/explore, zone entries with controller changes) and one replacement-action parser producing `ReplacementAction` (instructions via the effect parser, prevent/redirect, modify amount: plus one/twice/set to N).
2. "The next time/next N damage ... this turn" one-shot shields: `AddReplacement` with uses/amount and duration.
3. ETB replacements: "As ~ enters, [choice]" (choice stored for linked abilities, CR 607) and "enter as a copy ... except" (BecomeCopyExcept / EnterCopyExceptions exist) — unify with etb_choices*.rs.

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
