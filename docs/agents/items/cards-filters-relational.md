# cards-filters-relational: Object-phrase grammar I: relational filters ("with lesser mana value", "with the greatest power among", "total mana value N or less", "that shares a creature type with", "other than", history-qualified objects) — 318 texts / 323 cards (290 unlocked alone)

SCOPE: 318 unsupported ability texts (318 on paper cards) blocking 323 paper cards; 290 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-filters-relational.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Object filters that relate the object to another object, a value or a group: comparisons with a referent ("target creature an opponent controls with greater power", "a creature card with lesser mana value", "creatures with power less than that creature's power", "with mana value less than or equal to the number of lands you control"), extremes ("the creature with the greatest power among creatures target opponent controls", "with the lowest mana value"), group constraints on multi-selections ("any number of target creature cards with total mana value 6 or less", "up to two target creatures with total power ..."), sharing ("each other creature that shares a color with it", "a card that shares a color with a legendary creature you control", "spells you cast that share a card type with the exiled card", "with the same name as"), exclusions ("other than enchanted creature", "other than ~"), and history-qualified objects ("target creature that dealt damage to you this turn", "creatures that blocked or were blocked by it this turn", "each creature dealt damage this way").

APPROACH: 1. Extend `phrases::parse_object_phrase` with a pluggable suffix-parser hook (a small registry like the other pattern kinds, e.g. `FilterSuffixPattern`) so relational suffixes live in this item's files instead of growing phrases.rs; land the hook first in a tiny commit (cards-filters-noun-phrases edits the adjective/noun core of phrases.rs in parallel).
2. Relational filters need a value on the other side: `Filter::Compare { stat, cmp, value: Value }` where the value may mention a referent (Sel) or a count — evaluated with the ability's context. Extremes: `Filter::Extreme { stat, max/min, among: Filter }` (ties allowed, CR wording "or tied for").
3. Group constraints: targets/selections with a total (`TargetSpec` group constraint: sum of stat ≤ value), checked when targets are chosen (CR 601.2c) and on resolution; non-target "any number of ... with total ..." selections use the same check.
4. History-qualified filters reuse the event query of cards-history-conditions (DealtDamageThisTurn, AttackedThisTurn exist; add BlockedOrWasBlockedBy, DealtDamageBy(src), DealtDamageThisWay).

PARSER FILES INVOLVED: oracle/phrases.rs (parse_object_phrase and its suffix parsers: parse_with_suffix, parse_stat_suffix, parse_chosen_suffix), patterns/edict_greatest_power.rs, patterns/same_name_as_that.rs, patterns/total_power_keep.rs, patterns/r608_cast_from_looked_at_hand.rs

FILES THIS ITEM OWNS: new oracle/patterns/filters_relational.rs (+ the suffix hook in phrases.rs); may edit edict_greatest_power.rs, same_name_as_that.rs, total_power_keep.rs; eval.rs for new Filter variants; stack.rs/target_rules.rs for group target constraints

ENGINE CAPABILITIES: Filter AST has Power/Toughness/ManaValue comparisons with constants, SharesCreatureType/CardType/Color, SameNameAs, DealtDamageThisTurn — MISSING: comparisons against a dynamic Value/referent, extreme-among filters as general filters, and group (total) constraints on multiple targets or selections (CR 601.2c legality of the target set).

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
