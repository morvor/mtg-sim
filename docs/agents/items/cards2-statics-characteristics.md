RULES NOTES:
- Layers: CR 613.1 (layers 1-7), 613.1a/613.2a (copy effects and copiable values; names set in copy exceptions are copiable, 707.9b), 613.1c (text-changing, CR 612.1-612.2: only words used in the correct way change), 613.1d (type-changing), 611.2c (a resolving effect's affected set is locked when it begins), 611.3a (a static ability's effect isn't locked in), 611.3c (characteristic changes apply simultaneously with entering), 604.3 / 604.3a (characteristic-defining abilities, separate for power and toughness), 113.6a (CDAs function everywhere), 113.6b (an ability that says where it functions).
- Returning as an Aura: CR 303.4f (choose what it enchants as it enters). Bronzehide Lion rulings: you choose a creature you control as it returns; with nothing legal to enchant it stays in the graveyard; a token copy doesn't return; a nontoken copy returns as an Aura with only the two granted abilities.
- Biotransference ruling: replacement effects that modify how artifacts enter apply to creatures it makes artifacts (the type change applies before entering replacements).
- Protection: CR 702.16a (protection from a quality), 702.16k (protection from a player). Death-Mask Duplicant rulings: it gains every landwalk and protection ability of the imprinted cards, including protection from a quality other than a color.
- Hexproof and ward: CR 702.11b/e, 609.4. Nowhere to Run rulings: ward abilities of creatures your opponents control don't trigger while it's on the battlefield, whether or not they have hexproof; if it leaves while a spell targets a hexproof creature, that target becomes illegal.
- Casting restrictions: Fires of Invention rulings: it looks at the whole turn (spells cast before it entered count); a countered spell counts; it overrides permissions to cast during another player's turn or a third spell.
- Names: CR 201.2a (same name), 201.5 (text that refers to the object it's on by name means only that object), 207.2c-d (ability words and flavor words have no rules meaning: strip them, including ones with commas or ellipses).

COMMON RULES FOR CARD ITEMS (round 2):
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (the Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- Texts marked "also needs <round-1 item>" belong to a round-1 item that is still in progress for one construct and to this item for the other. Do your construct; if that item has landed when you finish, make the whole text work, otherwise list the text as waiting for it. A text can also contain a second construct that the probes didn't reach: fix it when it is small, otherwise list it with the item that owns that area.
- One-offs. The hand-written mechanism exists (src/cards/, `ManualAbility`, `mtg-tools manual-check`; policy in src/cards/mod.rs). If a text here turns out to be a genuine one-off (no other card shares the construct), don't force a pattern: list it in your report for cards-manual-defs-2. Never hand-write a construct that two or more cards share.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Build hygiene (CLAUDE.md): `export CARGO_BUILD_JOBS=2`, one cargo build at a time per worktree, no second checkout for before/after numbers.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage`, the baseline filters (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`) and `mtg-tools unsupported --card "<Name>"` for the listed cards. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour (TestGame tests per family with real cards; for statics on other zones, test a card in hand and a spell on the stack) and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate). Re-run `mtg-tools card-coverage` after the normalizer change: it can change many cards.
