# cards4-paper-combat-statics: Combat, static, characteristic, history and trigger grammar for the paper cards the tools counted as digital: combat damage choices, block requirements and restrictions, untap restrictions over groups, protections and permissions, P/T definitions, history conditions, state and play triggers, activation limits — 35 texts / 32 cards (32 unlocked alone)

SCOPE: 35 unsupported ability texts on paper cards, blocking 32 paper cards; all 32 become fully supported when this item alone is done. These cards are legal in paper formats (Legacy, Vintage, Premodern, Commander, ...), but the tools counted them as digital-only because their Scryfall oracle record is an MTGO-only reprint (Masters Edition I-IV, Tempest Remastered, Vintage Masters), so no earlier round planned them (they sat in the unscheduled cards-digital-alchemy list). Item paper-scope-1 fixes the tools; cards4-paper-plan planned the texts (card-support-plan-4.md, "Paper-scope texts"). Each text was probed (round3/autoprobe.py) and drilled to the failing words (round4/drills.tsv, ids `P-...`). The full list ships as items/cards4-paper-combat-statics.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece, family, previous item, note). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Compile combat damage choices ("you may have it assign no combat damage this turn", "If that player does, the attacking creature assigns no combat damage this turn"); block grammar ("Creatures it was blocking that had become blocked by only ~ this combat become unblocked", "It blocks each attacking creature this turn if able", "creatures that blocked ~ this turn", "can't attack unless at least two other creatures attack", "Except for creatures named ~ and artifact creatures, creatures you control can't attack"); untap restrictions ("Each attacking creature and each blocking creature doesn't untap during its controller's next untap step", "next two untap steps", "deals N damage to any target and doesn't untap during your next untap step"); statics ("can't be enchanted", "other players can't gain control of them", "its activated abilities with {T} in their costs can't be activated", "can be the target of spells and abilities controlled by target player as though it didn't have shroud", "You may play any number of lands on each of your turns"); characteristics ("equal to the number of Forests sacrificed as it entered", "~'s power becomes the total power of those creatures", "During your turn, ~'s power and toughness are each equal to ...", "for each other attacking ~", names with commas, the most common color of a chosen player's nontoken permanents, printed toughness "7-*"); history ("each opponent and planeswalker it has dealt damage to this game", "has blocked or been blocked since your last upkeep", "if ~ regenerated this turn ... for each time it regenerated this turn", "if ~ started the turn untapped", "if it wasn't sacrificed", "if it wasn't the first land you played this turn"); trigger events ("When ~'s power is N or greater", "When you play another land", a four-way "or" subject, the most-common-color state trigger); activation limits ("Activate no more times each turn than the number of snow Swamps you control", a counter condition in a modal header).

COMMON RULES FOR CARD ITEMS (round 4, paper-scope texts):
- These texts were never in a card item: the tools counted their cards as digital-only until paper-scope-1, so they sat in the unscheduled cards-digital-alchemy list (column previous_item). Many are first-edition wordings the compiler has never seen. The plan probed every text: column failing_piece is the first failing sentence (or cost, trigger, line), and column note has the drilled failing words ("drilled: ... compiles; ... fails", with the drill ids of round4/drills.tsv) and the second failing piece. Re-probe before starting a family (`docs/agents/round3/probe.py --card "<Name>" --text "<edited text>"` compiles edited texts as variants of the real card, with its other paragraphs and types, in one run of the release mtg-tools; it picks the first oracle record of the name, so for a name that tokens share, such as Shapeshifter, check the record; `mtg-tools unsupported --text "<text>" --type "<type line>" [--ast]` compiles one bare text).
- Before paper-scope-1 lands, `mtg-tools unsupported --paper` and `card-coverage` don't count these cards; use `mtg-tools unsupported --card "<Name>"` (no --paper) to measure them, and `docs/agents/round4/check_plan.py --live`, which applies the paper rule itself.
- Where a text fails because the engine can't do it (the engine need in each family), build the engine part first and test it with a custom card before the grammar.
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (the Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised). Judgment calls go in the interpretation register (docs/interpretations/, `interp!`).
- One-offs. The hand-written mechanism exists (src/cards/, `ManualAbility`, `mtg-tools manual-check`; policy in src/cards/mod.rs). The plan searched every one-off-looking construct over all in-scope paper cards (by format legality, so including these cards); the genuine one-offs are in cards4-manual-defs. Several texts here have wording no other card uses (Telekinesis' "two untap steps", Withering Wisps' counted limit, Fastbond's "any number of lands", Blaze of Glory's "each attacking creature") but extend a supported construct by a count or a set, so they are grammar, not one-offs. If a text here turns out to be a genuine one-off (search the card data before deciding), don't force a pattern: list it in your report for cards4-manual-defs. Never hand-write a construct that two or more cards share.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Build hygiene (CLAUDE.md): `export CARGO_BUILD_JOBS=2`, one cargo build at a time per worktree, no second checkout for before/after numbers.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage`, the baseline filters (`mtg-tools unsupported --limit 500 --filter "<s>"`) and `mtg-tools unsupported --card "<Name>"` for the listed cards. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour (at least one TestGame test per family with a real card) and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate, proposed deferral).
