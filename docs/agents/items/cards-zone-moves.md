# cards-zone-moves: Card-flow grammar III: zone moves ("return/put [cards] from [zone] to/onto [zone] [modifiers]") — 342 texts / 348 cards (294 unlocked alone)

SCOPE: 342 unsupported ability texts (342 on paper cards) blocking 348 paper cards; 294 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-zone-moves.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: One grammar for moving objects between zones: VERB (return/put/shuffle/exile) + OBJECT PHRASE with zone qualifiers ("cards exiled with ~", "from your hand or graveyard", "from your hand and/or graveyard", "in your graveyard that were put there from the battlefield this turn", "a creature card put into a graveyard this way", "up to one target artifact card and up to one target enchantment card") + DESTINATION (hand, battlefield, library top/bottom/position, graveyard, exile, command zone) + MODIFIERS (tapped, tapped and attacking, face down, under [player]'s control, attached to [object], with [counters], transformed, "at the beginning of the next end step" handled by delayed-reflexive). Includes owner-side moves ("each player returns all ... from their graveyard to the battlefield", "to their owners' hands") and bounce of your own permanents as an effect.

PHRASE FAMILIES (texts in family; representative failing pieces and cards):
- "return/put ... from [zone] to/onto [zone]" with zone-qualified objects ("cards exiled with ~", "from your hand or graveyard"): 65. e.g. "put all cards exiled with ~ into their owner's graveyard." - moves with modifiers ("with an additional +1/+1 counter", "attached to ~", "face down", "tapped and attacking", "under your control"): 68. e.g. "return it to the battlefield tapped under its owner's control." - other (mixed; read the texts): 44. e.g. "put it into your hand." [Sapling of Colfenor]; "put that card into your hand." [Spoils of the Vault]; "Put each creature card milled this way onto the battlefield." [Random Encounter]

APPROACH: 1. Build the move clause parser once (verb + object + from-zone + to-zone + modifiers) targeting `Effect::Move`/`Destination` and route the existing ad-hoc return/put patterns through it where they are subsets.
2. Object phrases with zone qualifiers and multi-target conjunctions reuse phrases.rs; "exiled with ~" = linked set (CR 607); "this way" sets = stored results (see cards-values-results).
3. Modifiers map to Destination fields; "with a +1/+1 counter on it" = enters-with replacement (CR 614.1c), "attached to" = enters attached (CR 303.4f).

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
