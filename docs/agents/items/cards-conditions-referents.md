# cards-conditions-referents: Condition grammar I: conditions about referents ("if it/that creature/the sacrificed card ...", "if you do/can't", "... this way") — 457 texts / 457 cards (422 unlocked alone)

SCOPE: 457 unsupported ability texts (457 on paper cards) blocking 457 paper cards; 422 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-conditions-referents.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Make conditions compositional: SUBJECT + PREDICATE, where the subject is resolved by the same referent machinery the effect parser uses (it, its, that creature/card/player/spell, the sacrificed/exiled/discarded/revealed/milled card, enchanted/equipped creature, X, they) and the predicate is any object/player state phrase the filter and player-filter grammar already understands (is/was [type, color, supertype, token, attacking, tapped, legendary], has/had [keyword, counters, power N or greater], shares a [type] with ..., its mana value is/was N or less, controls ..., has N or more cards in hand). Today `statics::parse_condition(c, ctx)` gets no Builder, so a condition can't see what "it" or "that creature" means; `effects::parse_sentence` only falls back to `statics_conditions::pronoun_state` when a whole "If ..., ..." sentence fails, and trailing conditions ("draw a card if it was attacking", "... instead if that target is a creature") and intervening-if clauses about the trigger object ("Whenever a creature dies, if it had a -1/-1 counter on it, ...") are handled only by special patterns.

PHRASE FAMILIES (texts in family; representative failing pieces and cards):
- "if it/that X is/was/has ..." about a referent object (type, color, P/T, counters, token, attacking): 233. e.g. "if that player has two or fewer cards in hand" [Hellfire Mongrel]; "if it was a Human" [Slayer's Plate]; "if that player controls a nonblack" [Urborg Stalker]
- "[effect] if it/that X ..." trailing condition about a referent: 82. e.g. "draw a card if it has flying." [Miles "Tails" Prower]; "Destroy target creature if it's white." [Soul Rend]; "Destroy target creature if it shares a color with the most common color among all permanents or a color tied for most common." [Tsabo's Assassin]
- "if a/an [filter] was [verb-ed] this way" existential over the previous effect: 49. e.g. "If you search your library this way, shuffle." [Travel Through Caradhras]; "If a player is dealt damage this way, scry N." [Play with Fire]; "If damage is prevented this way, ~ deals that much damage to any target." [Acolyte's Reward]
- "if you do / don't / can't / if they do" outcome of a previous instruction: 19. e.g. "If you can't, ~ deals N damage to you." [Lord of the Pit]; "If you can't, sacrifice ~." [Eldrazi Monument]; "Whenever a nontoken creature you control enters, if you didn't cast it from your hand, it gains haste until your next turn." [Chainer, Nightmare Adept]
- "if X is N or more" (X of the spell/ability): 12. e.g. "If X is N or more, scry N." [Roku's Mastery]; "If X is N, you may choose a player." [Multiple Choice]; "If X is N or more, also create X N/N white Angel creature tokens with flying and vigilance." [Finale of Glory]
- cost-reduction conditions referring to targets ("if it targets ..."): 3. e.g. "Counter target spell if you control more creatures than that spell's controller." [Unified Will]; "if another opponent controls one or more nonland permanents that spell could target" [Exterminator Magmarch]; "target opponent discards a card if you control the creature with the greatest power or tied for the greatest power." [Triumph of Cruelty]
- other (mixed; read the texts): 59. e.g. "if a card is exiled with it" [Redemptor Dreadnought]; "if a card is exiled with it" [Smirking Spelljacker]; "if no opponent has more life than that player" [Veteran Soldier]

APPROACH: 1. Add a Builder-aware condition entry point (e.g. `parse_condition_with(c, b) -> Option<Condition>`) that first tries a subject-predicate parse (subject via `effects::object_ref`/`player_ref`, predicate via `phrases` filters / `statics_conditions` state phrases → `Condition::SelMatches(sel, filter)` / `PlayerMatches` / `Compare(Value..)`), then falls back to `statics::parse_condition`. Use it for leading "If ..., ", trailing " if ..." (with and without "instead"), "Otherwise, ...", and in `triggers.rs` for intervening-if clauses, where "it" means the trigger object (look-back `Sel::TriggerLki` for leaves-the-battlefield triggers, CR 603.10a).
2. "this way" existentials: "If a creature card was exiled this way", "If a land card is revealed this way", "If that creature dies this way", "If you discarded a card this way" → a condition over the set the previous instruction affected (store it with `Effect::Store`/`vars`, then `Condition::SelNonEmpty`/`SelMatches`). Share the stored-set convention with cards-values-results ("for each card exiled this way") — agree on one helper.
3. Outcome conditions: "If you do/don't/can't", "If they do", "If that player doesn't", "For each opponent who can't" → `Condition::PrevHappened` generalized to the instruction's performer and to "can't" (impossible to perform). "If X is N or more" → `Compare(Value::X, ..)`.
4. Comparisons between referents ("if it has greater power or toughness than ~", "if its power is greater than ~'s power") reuse the value grammar (`statics::parse_value_phrase`).
5. Keep the pronoun-hardening invariant: a pronoun without an antecedent must still fail (oracle_hardening_referents.rs).

PARSER FILES INVOLVED: oracle/effects.rs (parse_sentence, parse_leading_if, parse_clause), oracle/statics.rs (parse_condition, parse_condition_core), oracle/triggers.rs (intervening if), patterns/statics_conditions.rs (pronoun_state), patterns/conditional_parts.rs, patterns/conditional_followups.rs, patterns/r608_if_its_a_card.rs, patterns/card_flow_reveal_if.rs, patterns/oracle_hardening_referents.rs

FILES THIS ITEM OWNS: new oracle/patterns/conditions_referents.rs (+ conditions_this_way.rs); may edit statics_conditions.rs, conditional_parts.rs, conditional_followups.rs, r608_if_its_a_card.rs; small hook edits in effects.rs/statics.rs/triggers.rs (coordinate: cards-history-conditions and cards-conditions-state-unless also add condition phrases — they plug into the same entry point via ConditionPattern; land the Builder-aware entry point early in its own commit)

ENGINE CAPABILITIES: The Condition AST already has SelMatches/PlayerMatches/Compare/PrevHappened/SelNonEmpty; evaluation of stored sets from earlier instructions exists (vars). Likely gaps: (a) "can't" outcomes (an instruction that was impossible, e.g. "sacrifice a creature. If you can't, sacrifice ~") need the resolver to record whether an instruction could be performed; (b) conditions on the last known information of an object that left a zone during the same resolution ("If that creature was a Human" after destroying it) must use LKI.

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
