# cards-digital-alchemy: Digital-only cards (Alchemy mechanics: conjure, seek, perpetual, spellbooks, intensity, specialize, boons; and other digital-only printings) — outside the paper card-coverage metric — 939 texts (930 only on digital-only cards; 8 paper cards)

SCOPE: 939 unsupported ability texts (9 on paper cards) blocking 8 paper cards; 8 of those become fully supported when this item alone is done (the others also have a text owned by another item). These cards are NOT counted by card-coverage (paper only); this item is optional for the 100% goal and runs last. The full list, with the failing piece found by compiler probes, ships as items/cards-digital-alchemy.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: These texts block only digital-only cards (MTG Arena/Alchemy, games without "paper"), which `mtg-tools card-coverage` does not count (it measures paper cards: 31,099), plus a handful of paper cards using conjure/seek wording. Supporting them requires engine features that don't exist yet: perpetual modifications (characteristics changes that persist across zone changes), seek (random search with no shuffle), conjure into any zone (kw/conjure.rs exists for some forms), spellbooks and "draft a card from ~'s spellbook", intensity, specialize, boons, double team, heist. Many non-Alchemy digital texts (Arena-rebalanced "A-" cards) share wording with paper cards and will be fixed by the paper items — run this item LAST and re-measure first.

APPROACH: 1. Re-run `mtg-tools unsupported` (without --paper) after the paper items land; most non-Alchemy digital texts should be gone.
2. Implement the Alchemy engine features as keyword-action modules (kwa/ or kw/): perpetual = a per-card persistent modification list carried across zone changes (exempt from CR 400.7 by design), seek = random selection from library, spellbooks = per-card card-name lists from Scryfall `all_parts`/data (check availability in data/), draft-from-spellbook = conjure a random spellbook card.
3. Only then parse the wording.

PARSER FILES INVOLVED: patterns/conjure.rs, kw/conjure.rs, and the pattern files of the construct items

FILES THIS ITEM OWNS: new src/kwa/seek.rs, src/kwa/perpetual.rs (or kw/), patterns/alchemy_*.rs

ENGINE CAPABILITIES: MISSING: perpetual, seek, spellbooks, intensity, specialize, boons, heist. Data: spellbook contents may not be in the Scryfall bulk files in data/ (check `all_parts`); if absent, flag to the owner.

BASELINE (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`; counts include other items' texts and digital-only cards): `perpetually` → 239 texts / 240 cards; `seek` → 112 texts / 112 cards; `conjure` → 123 texts / 123 cards; `spellbook` → 60 texts / 64 cards; `intensity` → 21 texts / 40 cards

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
