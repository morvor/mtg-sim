# oracle-roundtrip: Compile check for every card: render compiled abilities back to Oracle text and compare

WHY: the engine runs each card's compiled abilities (ability.rs AST), not its text. Cards worded slightly differently can compile differently, and a parser that silently drops or misreads a word ("nontoken", "you control", "up to", "until end of turn", "another", "each opponent" vs "target opponent", "may") produces a card that misbehaves only in some situations. Rulings tests can't catch this on the ~31,000 cards, so every card the compiler accepts must be checked automatically.

GOAL: for every fully supported card, prove the compiled abilities say exactly what the Oracle text says, by rendering the AST back into canonical Oracle-style English and comparing.

1. Renderer: crates/mtg-engine/src/oracle/render.rs (or a render/ module): renders every AST node (keywords with parameters, costs, activated/triggered/static/spell abilities, effects, selections and filters, targets, values, conditions, durations, replacement and prevention effects, modes, restrictions, linked abilities, card-kind structures like sagas, classes, adventures, rooms, DFC faces) into the wording Wizards uses. Write it INDEPENDENTLY of the parser: generate text from the AST's meaning; never reuse the parser's phrase tables or keep the source text around to print it back, since the check is only worth something if the two directions are separate derivations. Every AST variant must render (no catch-all that prints a placeholder silently; an unrenderable node is reported as a mismatch).
2. Comparison: normalize both sides the same way (reminder text removed, the card's own name and 'this creature/permanent/spell' shorthand to ~, case, punctuation, whitespace, numbers in words vs digits). Allowed equivalences between different wordings that mean the same thing under the CR go in ONE explicit, commented list (each entry: the two forms and why they are equivalent, citing the CR where relevant). Keep it small; never add an equivalence to hide a real difference.
3. Tool: `mtg-tools roundtrip [--card NAME] [--filter TEXT] [--limit N] [--write docs/ROUNDTRIP.md]`: per card PASS or MISMATCH with the original and rendered text side by side, plus a summary (cards checked, passing, mismatches grouped by kind with counts and example cards). Make `card-coverage` also report 'fully supported and round-trip verified'.
4. Triage the mismatches: each is (a) a parser bug: the AST doesn't mean what the text says (fix the parser or make the text unsupported, with a test showing the in-game difference); (b) a renderer gap: fix the renderer; (c) a true equivalence: add to the list with justification. Fix as many parser bugs as you can in this item, biggest clusters first, and report the remaining mismatch clusters with counts (follow-up items will take them).
5. Tests: renderer unit tests over representative real cards of each AST area; a regression test that fails if a card that passed starts mismatching (e.g. a checked-in list of passing cards that must stay passing, or a minimum pass count updated by --write); in-game tests for each parser bug fixed.

DONE when the tool runs over every supported card, docs/ROUNDTRIP.md records the numbers, the AST renders completely, and the parser bugs found are fixed or listed by cluster in remaining_gaps.
