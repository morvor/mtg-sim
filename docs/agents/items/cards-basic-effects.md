# cards-basic-effects: Basic effect verbs with complex arguments: counter spells/abilities with qualifiers, damage variants, "any number" selections, multi-target removal — 306 texts / 315 cards (275 unlocked alone)

SCOPE: 306 unsupported ability texts (306 on paper cards) blocking 315 paper cards; 275 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-basic-effects.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: The remaining failures of common verbs: countering with qualifiers ("Counter target activated ability from an artifact source", "Counter target activated ability, triggered ability, or noncreature spell", "Counter target spell with {X} in its mana cost unless its controller pays {2}"), damage variants ("deals 2 damage to each of up to one target creature, up to one target player, and/or up to one target planeswalker", "it deals that much damage to any target that isn't a Dinosaur", "Up to two target creatures you control each deal damage equal to their power to target creature an opponent controls", "~ deals 3 damage to each creature dealt damage this turn"), "any number" selections as effects ("tap any number of untapped creatures you control", "sacrifice any number of artifacts", "exile any number of other nonland permanents you own and control"), multi-target removal ("Destroy up to one target artifact, up to one target creature, and up to one target land"), P/T multipliers ("double target creature's power X times", "gets twice -X/-X", "gets an additional -1/-1 for each"), and odd verbs (clash, blight, "bands with other", "the same is true for ...").

APPROACH: 1. Countering: `p_counter_spell` accepts stack-object filters (spell/activated/triggered ability with source filters) — CR 701.6.
2. Damage: plural sources ("each deal damage equal to their power" → ForEach source), recipient lists with "up to one target" per type, "that much" amounts, filters on recipients.
3. "Any number of [filter] you control": a selection of objects (non-targeted) as the object of tap/sacrifice/exile, then "for each ... tapped this way" follow-ups (stored set).
4. Multi-target lists: "up to one target A, up to one target B, and/or up to one target C" → several TargetSpecs (coordinate with cards-filters-noun-phrases for the list grammar).

PARSER FILES INVOLVED: oracle/effects.rs (p_damage, p_counter_spell, p_destroy, p_exile, p_sacrifice, p_tap_untap, p_pump), patterns/damage_removal*.rs, r120_damage.rs, a701_actions.rs, sweep_long_tail_targeted.rs, sweep_long_tail_combat.rs, combat.rs

FILES THIS ITEM OWNS: new oracle/patterns/basic_effects_ext.rs; may edit damage_removal.rs, damage_removal_sources.rs, damage_removal_exile_edict.rs, r120_damage.rs, a701_actions.rs, sweep_long_tail_targeted.rs and the p_* functions in effects.rs

ENGINE CAPABILITIES: CounterSpell may only take spell filters — countering abilities with source filters needs StackObject filters (stack_ability_filters.rs exists). Doubling power X times = Modification with a computed value.

BASELINE (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`; counts include other items' texts and digital-only cards): `counter target activated ability` → 7 texts / 7 cards; `each deal damage equal to their power` → 8 texts / 8 cards; `tap any number of` → 15 texts / 17 cards; `sacrifice any number of` → 27 texts / 30 cards; `up to one target artifact, up to one target creature` → 5 texts / 5 cards

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
