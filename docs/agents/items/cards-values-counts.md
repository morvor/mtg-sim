# cards-values-counts: Value grammar I: counts and aggregates ("for each [X]", "where X is the number of [X]", "greatest/total power among", "number of [types/colors] among") — 397 texts / 399 cards (349 unlocked alone)

SCOPE: 397 unsupported ability texts (397 on paper cards) blocking 399 paper cards; 349 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-values-counts.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Any numeric slot of any instruction should accept a value phrase, and value phrases should be parsed by one grammar: `the number of [object phrase in zone]`, `the number of [player phrase]` (opponents you have, players being attacked), `[referent]'s [stat]`, `the greatest/least [stat] among [object phrase]`, `the total [stat] of [object phrase]`, `the number of [card types | colors | basic land types | creature types | different mana values | different names] among [object phrase]`, counters (`the number of [kind] counters on [ref]`, `experience counters you have`), arithmetic (`N plus ...`, `twice ...`, `half ..., rounded up/down`, `... minus ...`), and the multiplier forms `[instruction] for each [object/player phrase]` and `create a number of [tokens] equal to ...`. Most failing texts here are ordinary instructions whose value phrase or whose X slot isn't understood ("look at the top X cards ..., where X is ...", "earthbend X, where X is ...", "investigate for each goaded creature you control", "Put X +1/+1 counters on target creature, where X is that creature's mana value").

PHRASE FAMILIES (texts in family; representative failing pieces and cards):

- aggregates: "greatest/least/total power|toughness|mana value among ...": 39. e.g. "~ deals damage to that player equal to their total power." - other (mixed; read the texts): 47. e.g. "you may collect evidence X." [Incinerator of the Guilty]; "draw cards equal to the difference." [Doctor Octopus, Master Planner]; "you may gain life equal to the power of target creature you control." [Wall of Reverence]

APPROACH: 1. Consolidate `statics::parse_value_phrase` and `patterns/r107_numbers.rs::value_phrase` into one compositional value parser: noun-phrase counts call `phrases::parse_object_phrase` (with zone suffixes "in your graveyard", "in all graveyards", "you own in exile"), player counts call the player grammar, stats on referents call `effects::object_ref`.
2. Add a general aggregate value (e.g. `Value::Aggregate { stat: Power|Toughness|ManaValue|Counters(kind)|..., op: Max|Min|Sum|CountDistinct, over: Filter|Sel }`) and a distinct-count over characteristics (`DistinctAmong { what: CardTypes|Colors|CreatureTypes|ManaValues|Names|BasicLandTypes, over }`), and route the existing GreatestPower/GreatestManaValue/CardTypesAmong/ColorsAmong/DistinctNames/Domain through it (keep old variants as thin wrappers if removing is too invasive).
3. Make "where X is ..." and "for each ..." generic rewrites usable by every effect pattern (the substitution in r107_numbers.rs already exists — the failures are value phrases and X in slots like "the top X cards", "X target creatures", "earthbend X", "connives X", "collect evidence X", "X/X token"). Audit effect patterns that take a number and make them accept `Value` instead of a literal.
4. "as you activate this ability" / "as ~ entered" lock-in values: note the timing (CR 107.3c vs 608.2h) in the AST if the engine distinguishes it.

ENGINE CAPABILITIES: Value AST has Count, GreatestPower, GreatestManaValue, CardTypesAmong, ColorsAmong, DistinctNames, Domain, Sum/Diff/Mul/Div/Min/Max — missing: least/greatest toughness, total power/toughness/mana value over a filter, distinct mana values / creature types / names among a filter generically, counts of player counters for arbitrary kinds may exist (PlayerCounters). Small eval.rs additions; no new subsystem.

BASELINE (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`; counts include other items' texts and digital-only cards): `where x is the number of` → 270 texts / 272 cards; `for each creature you control` → 19 texts / 19 cards; `greatest power among` → 37 texts / 37 cards; `total power` → 38 texts / 38 cards; `basic land types among` → 24 texts / 24 cards; `equal to the number of` → 222 texts / 224 cards

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
