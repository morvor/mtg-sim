# cards-library-dig: Card-flow grammar I: dig and distribute ("from among them", "the rest", "reveal until", "revealed this way", piles, library positions) — 275 texts / 280 cards (246 unlocked alone)

SCOPE: 275 unsupported ability texts (275 on paper cards) blocking 280 paper cards; 246 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-library-dig.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Compile the look/reveal/mill → choose → distribute → rest pattern as one grammar instead of fixed sentences: "Look at/Reveal the top N cards" | "mill N cards" | "exile the top N" | "reveal cards from the top until you reveal [N] [filter] card(s)" → "You may put/reveal [up to N] [filter] (card(s)) from among them/those cards/the revealed cards/the milled cards [into your hand | onto the battlefield (tapped)(with a counter)]" (also "Put all [filter] cards revealed this way into your hand") → "and/then put the rest [into your graveyard | on the bottom of your library in any/a random order | back in any order]" with optional "If you don't put a card into your hand this way, ...". Also piles ("separate them into a face-down pile and a face-up pile"), library positions ("third from the top", "on top in any order"), and "shuffle ~ and your graveyard into their owner's library".

PHRASE FAMILIES (texts in family; representative failing pieces and cards):

APPROACH: 1. A dig state machine in one pattern file: source step (look/reveal/mill/exile, N as Value, "until" with a filter and count) → zero or more selection steps (filter, count range, destination, optional, chooser — you/an opponent) → rest step. Each step parses with the shared object-phrase grammar (cards-filters-* may land in parallel; use phrases::parse_object_phrase).
2. Target the existing Effect::Dig / RevealUntil / Piles (piles.rs) / LibraryPosition; extend Dig with multiple selection steps and per-step destinations if needed.
3. Referents after the dig ("that card", "those cards", "the revealed card's mana value") must be stored for later sentences.

PARSER FILES INVOLVED: patterns/card_flow_dig.rs, card_flow_reveal_until.rs, card_flow_reveal_top_to_hand.rs, card_flow_put_one_and_other.rs, card_flow_from_among_milled.rs, card_flow_choose_one_of_them.rs, card_flow_put_into_graveyard_this_way.rs, r700_piles.rs, a701_manifest_pile.rs, sweep_long_tail_look.rs

FILES THIS ITEM OWNS: new oracle/patterns/dig_grammar.rs; may edit the card_flow_*.rs files listed (this item owns card_flow_* except card_flow_search.rs, card_flow_impulse.rs, card_flow_cast_while_exiled.rs)

ENGINE CAPABILITIES: Effect::Dig may support only one selection; multi-step distributions ("one into your hand, one on the bottom, and one into exile", "a land onto the battlefield and the rest into your hand") and opponent-chosen selections need Dig extensions (resolve.rs, library.rs). Piles exist (piles.rs).

BASELINE (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`; counts include other items' texts and digital-only cards): `from among them` → 180 texts / 182 cards; `the rest on the bottom` → 193 texts / 193 cards; `the rest into your graveyard` → 37 texts / 39 cards; `reveal cards from the top of your library until` → 56 texts / 56 cards; `revealed this way into your hand` → 26 texts / 26 cards

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
