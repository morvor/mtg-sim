# cards-conditions-state-unless: Condition grammar III: game-state conditions and "unless" (punisher choices, payment taxes, "as long as" states, comparisons between players) — 301 texts / 302 cards (258 unlocked alone)

SCOPE: 301 unsupported ability texts (301 on paper cards) blocking 302 paper cards; 258 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-conditions-state-unless.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Two linked constructs. (a) "unless": "[effect] unless [player] [action]" (punisher: "each opponent loses 3 life unless they sacrifice a nonland permanent of their choice or discard a card", "sacrifice it unless you return a basic land card from your graveyard to your hand", "unless any player pays {1}"), "[restriction] unless [player] pays {X} for each ..." (Ghostly Prison-style taxes with dynamic amounts and filters: "creatures can't attack you or planeswalkers you control unless their controller pays {X} for each of those creatures, where X is the number of enchantments you control"), and "unless [state]" ("~ can't block unless a creature with greater power also blocks", "sacrifice it unless an opponent was dealt damage this turn"). (b) State conditions not about a referent: player comparisons ("if an opponent controls more lands than you", "if a player has more cards in hand than each other player", "if no opponent has more life than that player"), compound control ("if an opponent controls a Forest and you control an Island"), aggregate states ("if creatures you control have total toughness 10 or greater", "if there are thirty or more counters among artifacts and creatures you control", "five or more mana values among cards in your graveyard"), source-zone states ("if ~ is on the battlefield", "if ~ is the only creature card in your graveyard").

APPROACH: 1. One `Effect` shape for punishers: the affected player chooses between performing the alternative (an Effect, possibly itself a choice: "sacrifice X or discard a card") and suffering the effect; reuse the existing "unless that player pays" machinery (patterns/r118_unless_that_player_pays.rs, sweep_long_tail_unless.rs) generalized from mana to any cost-like instruction (CR 118.12: an "unless" cost may be any action). Make "unless [state condition]" compile to `If(Not(cond))`.
2. Attack/block taxes with dynamic amounts and per-creature multipliers → the existing restriction-with-cost machinery (Propaganda-style), with Value support ("{X} ... where X is", "for each creature they control that's attacking you").
3. Player-comparison conditions: `Compare(Value::Count(..) of opponent, Cmp, Value of you)` quantified over opponents ("an opponent" = exists, "each other player" = forall); add a quantified player condition if missing.
4. Aggregate state conditions reuse the aggregate Value from cards-values-counts (coordinate: `Value::Aggregate`/`Count` over filters) — if that item hasn't landed, add the minimal value variants here behind the same names.

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
