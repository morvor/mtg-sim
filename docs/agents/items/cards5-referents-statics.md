COMMON RULES FOR CARD ITEMS (round 5):
- These texts are the long tail: every one was in at least one landed item (column previous_item) and is still unsupported after it, most after two or three. The plan re-probed each (column failing_piece: the first failing sentence, cost, trigger or line) and drilled it (column note: "drilled: X compiles; Y fails", with the drill ids of round5/drills.tsv, and the second failing piece where there is one). Re-probe before starting a family (`docs/agents/round3/probe.py --card "<Name>" --text "<edited text>"` compiles edited texts as variants of the real card, with its other paragraphs and types, in one run of the release mtg-tools; `mtg-tools unsupported --text "<text>" --type "<type line>" [--ast]` compiles one bare text).
- Where a text fails because the engine can't do it (the engine need in each family), build the engine part first and test it with a custom card before the grammar.
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (the Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised). Judgment calls go in the interpretation register (docs/interpretations/, `interp!`).
- In flight while round 5 was planned: cards4-triggers-durations, cards4-costs-mana-replacements, cards4-paper-effects and cards4-manual-defs (round5/inflight.tsv). Two texts wait for their constructs (round5/pending-recheck.tsv). Don't build an in-flight item's construct here; if a text turns out to need one, list it in your report.
- One-offs. The hand-written mechanism exists (src/cards/, `ManualAbility`, `mtg-tools manual-check`; policy in src/cards/mod.rs). The plan searched every one-off-looking construct over all in-scope paper cards; the genuine one-offs are in cards5-manual-defs. If a text here turns out to be a genuine one-off (search the card data before deciding), don't force a pattern: list it in your report. Never hand-write a construct that two or more cards share.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.

- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage`, the baseline filters (`mtg-tools unsupported --paper --limit 500 --filter "<s>"`) and `mtg-tools unsupported --card "<Name>"` for the listed cards; `docs/agents/round5/check_plan.py --live` lists the snapshot texts supported since.
