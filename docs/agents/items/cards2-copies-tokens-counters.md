RULES NOTES:
- Spell copies: CR 707.10 (a copy of a spell is put on the stack, not cast), 707.10c (may choose new targets; may leave targets unchanged), 707.10d (a copy for each object it could target, put on the stack in the controller's order), 707.10e (a copy with a specified new target), 707.10f (a copy of a permanent spell becomes a token). Precursor Golem rulings: the controller of the original spell controls all the copies; copies have the same mode and X; Golems that couldn't be targeted are ignored; a spell targeting the same Golem twice still "targets only a single Golem". CR 115.7: changing targets (the new target must be legal; "the new target must be a player" is a further restriction).
- Copy exceptions: CR 707.9, 707.9b (modified characteristics become copiable values: a token copy of Jace, Mirror Mage that isn't legendary and has starting loyalty 1 passes that on to its copies, per its rulings), 306.5b (starting loyalty). Metamorphic Alteration rulings: copiable values locked in as the creature is chosen; a token is copied as originally created; it copies what the chosen creature copies; dies triggers of the copy work. Sakashima the Impostor rulings: no creature chosen means no exceptions apply; it can't copy itself.
- Tokens entering attacking or blocking: CR 506.3a/e/f, 508.4 (the controller chooses which player or planeswalker it attacks). Mirror Match rulings: the tokens block even creatures they couldn't normally block, were never declared as blockers (no "whenever blocks" triggers), and a noncreature token doesn't block.
- Token replacements: CR 614.1a, 111.10. Divine Visitation rulings: control-changing effects on creation apply first; a noncreature token that would become a creature as it enters isn't replaced; "The token's characteristics are entirely replaced", but "anything else specified in the effect creating the token (such as tapped, attacking ...)" still applies.
- Entering with counters: CR 614.1c, 614.12 (replacements that modify how a permanent enters, applied as it enters), 122.1b (keyword counters). Vastwood Hydra rulings: "You choose how the counters will be distributed when the ability resolves"; the distribution doesn't target (it is chosen on resolution, CR 608.2d; 601.2d's "each target receives at least one" is the rule for divisions announced while casting).
- Counters copied from an event: Bold Plagiarist ruling: "Your opponent places the counters on both permanents" (so another Bold Plagiarist of theirs doesn't trigger).

COMMON RULES FOR CARD ITEMS (round 2):
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (the Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- Texts marked "also needs <round-1 item>" belong to a round-1 item that is still in progress for one construct and to this item for the other. Do your construct; if that item has landed when you finish, make the whole text work, otherwise list the text as waiting for it. A text can also contain a second construct that the probes didn't reach: fix it when it is small, otherwise list it with the item that owns that area.
- One-offs. The hand-written mechanism exists (src/cards/, `ManualAbility`, `mtg-tools manual-check`; policy in src/cards/mod.rs). If a text here turns out to be a genuine one-off (no other card shares the construct), don't force a pattern: list it in your report for cards-manual-defs-2. Never hand-write a construct that two or more cards share.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Build hygiene (CLAUDE.md): `export CARGO_BUILD_JOBS=2`, one cargo build at a time per worktree, no second checkout for before/after numbers.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage`, the baseline filters (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`) and `mtg-tools unsupported --card "<Name>"` for the listed cards. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour (TestGame tests per family with real cards; for copies, check the copy's controller, targets and that it isn't cast) and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
