# cards2-filters-conditions: Target, filter and condition grammar III: variable and compound targets, relational filters against referents, noun-phrase qualities, comparison/parity/count conditions — 133 texts / 131 cards (125 unlocked alone)

SCOPE: 133 unsupported ability texts on paper cards (126 grammar; 3 engine; 1 with a second construct owned by an in-progress round-1 item ("also needs"); 3 former one-off claims re-checked as shared constructs), blocking 131 paper cards; 125 of those become fully supported when this item alone is done (the others also have a text owned by another item or wait for a round-1 item). The full list, with the failing piece found by compiler probes, ships as items/cards2-filters-conditions.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: The long tail of object phrases, targets and conditions. Targets: "each of X target creatures", "any number of target creatures, planeswalkers, and/or players. For each of them, ...", "Target creature you control and up to one other target legendary creature you control each deal damage ...", "for each graveyard with an instant or sorcery card in it, exile target instant or sorcery card from that graveyard", targets introduced inside a condition or comparison ("If target player has exactly 1 life", "with power greater than target creature's power"), "You can't choose an untapped creature as ~'s target as you cast it". Relational filters: comparisons against referents ("with lesser mana value than the creature that died", "with equal or lesser toughness"), "shares a color with the most common color among all permanents or a color tied for most common", same-name relations ("if another permanent with the same name is on the battlefield"), player-relative values ("with mana value greater than the number of lands that player controls"). Noun-phrase qualities: face-up, double-faced, "with {X} in their mana cost", "that has an Adventure", "with two or more card types", "that don't have a name", "that has an activated ability with {T} in its cost", "blocking or blocked by it". Conditions: parity ("if its mana value is odd", "if the number of permanents is even"), two counts compared, player comparisons ("if you control more creatures than each other player"), extremes with ties, counts on the battlefield ("as long as ten or more lands are on the battlefield", "three or more lands with the same name"), disjunctions and conjunctions.

RULES NOTES:
- Targets: CR 601.2c (targets are announced as the spell is cast; a spell may require some targets only if a mode or cost was chosen; a variable number of targets is announced first), 115.1, 115.4 ("any target", "two targets"); CR 115.3: the same object or player can't be chosen twice for one instance of the word "target" (Firestorm rulings: "The same permanent or player can't be targeted more than once"; X can't exceed the legal targets available). 608.2b: targets are rechecked on resolution, except restrictions that apply only "as you cast it": Enthralling Hold ruling: "affects only the choice of target as the spell is cast. If the creature becomes untapped before the spell resolves, it still resolves"; Dream Leash rulings: checked only if cast as a spell; an Aura put onto the battlefield or moved needn't satisfy it (it then only needs something it can legally enchant, CR 303.4f, 303.4j; the casting restriction isn't part of its enchant ability).
- Comparisons against a target or referent use the value on resolution (Fell the Mighty rulings: "Use the power of the target creature as Fell the Mighty resolves"; the creatures compared aren't targeted, and the target creature isn't destroyed; if the target is illegal nothing happens). Wretched Banquet ruling: "The creature's power is checked only as Wretched Banquet resolves."
- Names: CR 201.2a ("An object with no name doesn't have the same name as any other object"), 201.2c (different names), 708.2a (face-down permanents have no name; Pompous Gadabout rulings: "Face-down creatures don't have names unless an effect says otherwise"; losing a name after blocking doesn't remove the blocker).
- Qualities: CR 406.3 (face-up and face-down exiled cards), 712.1 (double-faced cards), 715.2 (Adventurer cards), 702.124m (doctor's companion), 105.4 (colors), 702.51a (convoke: "a creature that convoked ~").
- Conditions: Yennett, Cryptic Sovereign rulings: a card that isn't odd, or that you choose not to cast, means you draw instead; the revealed card stays on top (it is the card drawn). Players who left the game: CR 800.4, 800.4a.

COMMON RULES FOR CARD ITEMS (round 2):
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (the Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- Texts marked "also needs <round-1 item>" belong to a round-1 item that is still in progress for one construct and to this item for the other. Do your construct; if that item has landed when you finish, make the whole text work, otherwise list the text as waiting for it. A text can also contain a second construct that the probes didn't reach: fix it when it is small, otherwise list it with the item that owns that area.
- One-offs. The hand-written mechanism exists (src/cards/, `ManualAbility`, `mtg-tools manual-check`; policy in src/cards/mod.rs). If a text here turns out to be a genuine one-off (no other card shares the construct), don't force a pattern: list it in your report for cards-manual-defs-2. Never hand-write a construct that two or more cards share.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Build hygiene (CLAUDE.md): `export CARGO_BUILD_JOBS=2`, one cargo build at a time per worktree, no second checkout for before/after numbers.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage`, the baseline filters (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`) and `mtg-tools unsupported --card "<Name>"` for the listed cards. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour (TestGame tests per family with real cards; include tie cases for extremes and a resolution-time recheck for comparisons against targets) and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
