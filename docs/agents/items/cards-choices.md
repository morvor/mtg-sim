# cards-choices: Choice grammar: choose objects/players/types/names, random choices, "of the chosen type", "same name", named options — 317 texts / 318 cards (288 unlocked alone)

SCOPE: 317 unsupported ability texts (317 on paper cards) blocking 318 paper cards; 288 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-choices.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: Choices as first-class instructions whose results later sentences refer to: "Choose target opponent/player/another player" (then "that player"), "Choose a creature you control / up to three Doctors / a card exiled with ~" (then "the chosen creature", "that card"), "An opponent chooses one of them", "Each player chooses a creature type", choices at random ("a card at random from your graveyard", "an opponent at random", "choose 1, 2, or 3 at random", "any target chosen at random"), choice-dependent filters ("creatures of the creature type of your choice", "cards of the chosen type", "Basic lands of the first chosen type are the second chosen type", "the chosen card type"), name comparisons ("each other creature with the same name as it", "if it has the same name as a card in your graveyard"), named options ("each opponent chooses fame or fortune", "choose odd or even", "choose left or right", bidding).

APPROACH: 1. A `Choose` instruction parser: chooser (you/target player/each player/an opponent), what (object phrase incl. zone and "at random", player phrase, type/name/color/number/option list), how many (up to N, any number); bind the result as a named referent for later sentences (Builder::named / chosen_creature already exist).
2. Chosen-value filters: `Filter::ChosenType/ChosenName/ChosenColor/ChosenCardType` exist for ETB choices; extend to choices made during resolution (store in vars) and to "of your choice" inline choices.
3. Random choices use the engine RNG with the same AST plus a `random: true` flag (CR 701.? for random selections; no player decision).

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
