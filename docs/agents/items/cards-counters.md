# cards-counters: Counter grammar: put/remove/move/double counters with complex placement, counter-qualified groups, counter-linked abilities — 231 texts / 225 cards (185 unlocked alone)

SCOPE: 231 unsupported ability texts (231 on paper cards) blocking 225 paper cards; 185 of those become fully supported when this item alone is done (the others also have a text owned by another item). The full list, with the failing piece found by compiler probes, ships as items/cards-counters.texts.tsv (columns: cards blocked, normalized text, example card, piece kind, failing piece). Normalized text = reminder text removed, the card's own name as ~, numbers as N.

GOAL: "Put [N] [kind] counter(s) on [object phrase]" with any object phrase and value ("on each creature you control that didn't attack or enter this turn", "on that Hero for each creature blocking it", "your choice of a +1/+1 counter or two charge counters on up to one other target creature", "a +1/+1 counter and a counter from among flying, first strike, lifelink, or vigilance", "put the same number of each kind of counter on that creature"), removal ("remove all counters from up to one target permanent or opponent", "remove up to four charge counters", "remove two time counters from target permanent or suspended card"), moves and doubling ("move any number of +1/+1 counters from ~ onto other creatures", "double the number of +1/+1 counters on each creature"), counter-qualified groups ("creatures you control with counters on them", "with three or more +1/+1 counters on them", "each creature you control that you've put one or more +1/+1 counters on this turn"), and counter-linked abilities ("has all activated abilities of all cards in exile with brain counters on them").

PHRASE FAMILIES (texts in family; representative failing pieces and cards):

APPROACH: 1. Make `p_counters`/r122 patterns accept: counter lists ("a +1/+1 counter and a lifelink counter"), choices between counter kinds ("your choice of", "a counter from among ..." — keyword counters CR 122.1b), any count Value, any object phrase including players ("permanent or opponent": player counters), "up to N" removal, "all counters" of any kind.
2. Filters: `Filter::HasCounter` with kind/count comparisons; history "you've put counters on this turn" via cards-history-conditions' query (or a small TurnHistory field).
3. Note: countering spells/abilities ("counter target activated ability") is NOT this item (cards-basic-effects).

PARSER FILES INVOLVED: oracle/effects.rs (p_counters), oracle/costs.rs (counter_kind), patterns/r122_*.rs, counters_*.rs, a701_proliferate_repeat.rs, replacements_counter.rs (read-only; owned by cards-replacements)

FILES THIS ITEM OWNS: new oracle/patterns/counter_grammar.rs; may edit r122_*.rs, counters_*.rs, a701_proliferate_repeat.rs

ENGINE CAPABILITIES: AddCounters/RemoveCounters/MoveCounters/PutCountersOf exist; check choices among counter kinds and removing counters from players, "each kind of counter" iteration, doubling per kind.

BASELINE (`cargo run --release -q -p mtg-tools -- unsupported --limit 500 --filter "<s>"`; counts include other items' texts and digital-only cards): `put a +1/+1 counter on each creature you control that` → 3 texts / 3 cards; `remove all counters from` → 13 texts / 14 cards; `move any number of` → 11 texts / 11 cards; `with counters on them` → 10 texts / 10 cards; `counter from among` → 2 texts / 2 cards

COMMON RULES FOR CARD ITEMS:
- Generalize. Implement each construct as grammar (subject / verb / object phrase / qualifiers composed from phrases.rs, the value and condition parsers and the Builder's referent tracking), never one pattern per card wording; a fix should also cover wordings that aren't in the list. Unit-test the grammar on several real wordings.
- Faithfulness first. The parser must not accept text the engine doesn't implement exactly (an Oracle round-trip check audits every compiled card). For each family add TestGame tests with real cards that assert the in-game outcome (crates/mtg-engine/tests/cards/ or tests/cr/, citing cr!() for rules exercised and ruling!() for Scryfall rulings exercised).
- A text can contain a second failing construct owned by another item. Fix it when it is small; otherwise leave it and list it under remaining gaps with the owning item.
- One-offs. If a text's construct is genuinely unique (no other card shares it) and compiling it would be hacky, don't force it: once cards-manual-defs has landed, give it a hand-written definition in src/cards/ with a test; before that, list it as a manual candidate.
- Shared core files (oracle/effects.rs, phrases.rs, statics.rs, triggers.rs, costs.rs, ability.rs, eval.rs, resolve.rs) are edited by several items in parallel: keep edits there small (hooks, new enum variants handled everywhere), put grammar in this item's own pattern files, and merge origin often.
- Measure before and after: `cargo run --release -q -p mtg-tools -- card-coverage` and the baseline filters above. Report per family: texts fixed, texts remaining (each with a reason). Run `cargo run --release -p mtg-sim -- --random-decks --games 300` before finishing to catch panics in newly supported cards.
- DONE when about 90% or more of this item's texts compile with faithful, tested behaviour and every remaining text is listed with a reason (engine gap, belongs to item X, manual candidate).
