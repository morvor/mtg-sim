# Copy effects

Judgment calls about copiable values and copy effects (CR 707). Format and kinds:
`docs/agents/items/interpretation-register.md`; index: `docs/INTERPRETATIONS.md`.

## copy-exception-ability-stacks: An ability a copy exception grants is added again even when the copied values already have it
- Kind: interpretation
- Status: decided
- Rules: 707.9a "Some copy effects cause the copy to gain an ability as part of the copying process. This ability becomes part of the copiable values for the copy, along with any other abilities that were copied." / 707.3 "The copy’s copiable values become the copied information, as modified by the copy’s status (see rule 110.5). Objects that copy the object will use the new copiable values." / 113.2c "... If an object has multiple instances of the same ability, each instance functions independently. This may or may not produce more effects than a single instance; refer to the specific ability for more information." / Gigantoplasm ruling: "If the chosen creature is copying something else (for example, if the chosen creature is another Gigantoplasm), then Gigantoplasm enters the battlefield as whatever the chosen creature was copying (plus any abilities it gained as part of the copy process, if applicable)." / Phantasmal Image ruling: "The Illusion creature type and the triggered ability that Phantasmal Image gains as part of its copy effect are both copiable values that other effects may copy." / Vesuvan Doppelganger ruling: "A Vesuvan Doppelganger that becomes a copy of a Vesuvan Doppelganger (either itself or a different one) will gain another instance of its triggered ability." / Progenitor Mimic's ruling (2013-04-15): "If you choose to have Progenitor Mimic enter the battlefield as a copy of a creature, the triggered ability it gains will become part of its copiable values. For example, suppose Progenitor Mimic enters the battlefield as a copy of Runeclaw Bear, a 2/2 green Bear creature with mana cost {1}{G}. The resulting object is a 2/2 green Bear creature named Runeclaw Bear with mana cost {1}{G} and with “At the beginning of your upkeep, if this creature isn't a token, put a token onto the battlefield that's a copy of this creature.” If another Progenitor Mimic enters the battlefield as a copy of that creature, it will be a Runeclaw Bear with two instances of the triggered ability."
- Question: When a copy effect's exception grants an ability ("except it has '{X}: This creature has base power and toughness X/X.'") and the copied values already contain that ability (the copied object is another Gigantoplasm), does the copy have it once or twice? The CR doesn't say it outright.
- Decision: Decided by the ruling (Progenitor Mimic, 2013-04-15: "it will be a Runeclaw Bear with two instances of the triggered ability"; and Vesuvan Doppelganger's). Twice. The copied values (which include the first copy's gained ability, 707.9a) are copied, and then the exception adds its ability again; nothing merges identical abilities.
- Alternatives: Treat an exception's ability as not added when an identical one is already among the copied values (the copy has it once). For activated abilities like Gigantoplasm's this changes nothing visible; for triggered abilities (Vesuvan Doppelganger, Phantasmal Image's sacrifice trigger) it would halve the triggers.
- Why: 707.9a makes the gained ability part of the copiable values "along with any other abilities that were copied", 113.2c says multiple instances are independent, and the Vesuvan Doppelganger ruling says exactly this for a copy of a copy with the same exception. The Gigantoplasm ruling's "plus any abilities it gained as part of the copy process" points the same way: the second Gigantoplasm enters with the first one's gained ability and then gains its own. The judge audit (`docs/agents/reports/judge-audit-1.md`, rulings-18) agreed with medium confidence, noting that the CR doesn't say it outright; decided rather than provisional because the Vesuvan Doppelganger ruling settles the identical structure explicitly. The Progenitor Mimic ruling (found by the audit decision-audit-1, Nov 20; quoted by small-fixes-3) says it for an exception that grants a triggered ability, word for word the Question's case.
- Affects: copy effects with "except it has [ability]" copying an object that already gained that ability: for example Gigantoplasm, Vesuvan Doppelganger, Phantasmal Image and Cryptoplasm (count not measured).
- Code: `crates/mtg-engine/src/layers.rs` (layer 1, `Layer1::Copy`: exceptions applied on top of the copied values); `crates/mtg-engine/src/copy.rs` (`become_copy`, `add_copy_exceptions`).
- Tests: `tests/rulings/r_p023_enter_as_copy.rs` (`gigantoplasm_copying_another_gigantoplasm`, `phantasmal_image_copying_a_phantasmal_image_has_two_sacrifice_triggers`).

## copy-values-fixed-when-determined: A copy takes the copiable values the original has when the copy is determined
- Kind: interpretation
- Status: decided
- Rules: 707.2 "When copying an object, the copy acquires the copiable values of the original object’s characteristics ..." / 707.5 "An object that enters the battlefield “as a copy” or “that’s a copy” of another object becomes a copy as it enters the battlefield. It doesn’t enter the battlefield, and then become a copy of that permanent. If the text that’s being copied includes any abilities that replace the enters-the-battlefield event (such as “enters with” or “as [this] enters” abilities), those abilities will take effect. ..." / 614.12a "If a replacement effect that modifies how a permanent enters the battlefield requires a choice, that choice is made before the permanent enters the battlefield." / 707.2c "If a static ability generates a continuous effect that’s a copy effect, the copiable values that effect grants are determined only at the time that effect first starts to apply."
- Question: A copy's own copied "as this enters" ability can change the object it copies before the copy is on the battlefield: a token copy of Ixidron, or a Clone entering as a copy of Ixidron, turns "all other nontoken creatures" face down as it enters, the original Ixidron included. Does the copy copy Ixidron, or the face-down 2/2 the original has become?
- Decision: Decided by the user, Oct 28. Ixidron. A token "that's a copy of" an object takes the object's copiable values as the token is created; a permanent that enters as a copy of a chosen object takes them as the object is chosen (614.12a: before it enters). Effects applied as it enters don't change what it copies.
- Alternatives: Read the values as the copy effect starts to apply, when the permanent enters (707.2c's wording for static copy effects): the copy would then be a nameless face-down 2/2 whose copied ability it no longer has.
- Why: The copy effect is what gives the copy the "as this enters" ability that changes the original; letting that ability change what it copies is circular, and the token's characteristics are set by the effect that creates it. No ruling covers it; a judge could read 707.2c the other way for the Clone.
- Affects: copies of permanents with "as this enters" abilities that change other permanents (Ixidron; count not measured).
- Code: `crates/mtg-engine/src/replacement.rs` (`EtbInfo::copy_values`, `EtbInfo::copied_values`, set in `EnterAsCopy` and `AsEnters`); `crates/mtg-engine/src/actions.rs` (`token_entry`).
- Tests: `tests/cr/r707_009_copy_exceptions_and_values.rs` (`a_token_copy_copies_the_original_as_it_was_when_the_token_was_created`, `a_clone_copies_the_chosen_object_as_it_was_chosen`).

## copy-target-legality-original-or-copy: Copies made for each object a spell "could target" are decided from the original spell's point of view; a copy given a specified target is created only if the copy itself can target it
- Kind: interpretation
- Status: decided
- Rules: 707.10d "Some effects copy a spell or ability for each player or object it “could target.” The copies are put onto the stack with those targets in the order of their controller’s choice. If the spell or ability has more than one target, each of its targets must be the same player or object. If that player or object isn’t a legal target for each instance of the word “target,” a copy isn’t created for that player or object." / 707.10e "Some effects copy a spell or ability and specify a new target for the copy. If the spell or ability has more than one target, each of the copy’s targets must be that player or object. If that player or object isn’t a legal target for each instance of the word “target,” the copy isn’t created. ..." / 707.2 "When copying an object, the copy acquires the copiable values of the original object’s characteristics ..." / 608.2b "If the spell or ability specifies targets, it checks whether the targets are still legal. ..." Ink-Treader Nephilim's ruling (2006-02-01): "Even though you control the copies, the ability cares about who cast the original spell when determining which other creatures that spell could target. If the original spell has a targeting restriction that refers to "an opponent," the copies will see that from the perspective of the original spell's controller. For example, if your opponent casts a spell that says "Destroy target creature an opponent controls" targeting your Ink-Treader Nephilim, its ability will create a copy for each other creature the original spell could target: the rest of your creatures. However, since you control the copies, all the copies won't resolve for having illegal targets." Mirrorwing Dragon's ruling (2016-07-13): "Any creature the player controls that couldn't be targeted by the original spell (due to shroud, protection abilities, targeting restrictions, or any other reason) is just ignored by Mirrorwing Dragon's ability. If the spell has multiple targets, a given creature must be a legal target for all of them or else a copy won't be created for that creature." Beamsplitter Mage's ruling (2018-10-05): "In some rare cases, the original spell can target another creature but the copy can’t (most likely because an effect modified the characteristics of the original spell on the stack and won’t modify the copy). If the copy can’t target the chosen creature, the copy isn’t created." Ivy, Gleeful Spellthief's ruling (2022-09-09): "If Ivy, Gleeful Spellthief isn't a legal target for the spell, no copy can be created." Zevlor, Elturel Exile's ruling (2022-06-10): "... but if the chosen player or permanent isn't a legal target for the spell, the copy won't be created."
- Question: 707.10d and 707.10e end with the same words: if "that player or object isn’t a legal target for each instance of the word “target,”" the copy isn't created. A legal target for which spell: the original (cast by its controller, with its characteristics as they are on the stack), or the copy (controlled by whoever copies it, with only the original's copiable values, 707.2)? The two differ when the copy has another controller (Ink-Treader Nephilim copies an opponent's spell) or when an effect changed the original on the stack (Blind Seer made it another color).
- Decision: Decided by the user, Nov 5. A copy made "for each [object or player] that spell could target" (707.10d) is decided from the original spell's point of view: one copy for each object or player the original could target, even one the copy itself can't target; that copy is put onto the stack targeting it and, if its target is illegal as it resolves, it doesn't resolve (608.2b). A copy whose new target an effect specifies (707.10e: "Copy that spell. The copy targets the chosen creature.") is created only if that object or player is a legal target both for the original spell (the choices offered; Ivy's and Zevlor's "a legal target for the spell") and for the copy itself as it's put onto the stack (Beamsplitter Mage's ruling). Otherwise the copy isn't created: it never was on the stack, so nothing sees it being copied or becoming a target ("whenever you copy a spell" doesn't trigger).
- Alternatives: (a) The copy's point of view in both: Ink-Treader Nephilim would make no copies of an opponent's "destroy target creature an opponent controls" (its ruling says it makes them and they don't resolve), and the copies Mirrorwing Dragon's ruling describes would be decided by the copy. (b) The original's point of view in both: Beamsplitter Mage's copy would be created targeting a creature it can't target and be countered as it resolves, against its ruling, and "whenever you copy a spell" abilities would trigger for it. (c) For 707.10e, the copy's legality only: a copy could then target an object the original couldn't (Ivy's copy of an opponent's "target creature you control" spell targeting Ivy), against Ivy's and Zevlor's rulings read as speaking of the original.
- Why: 707.10d defines the copies by what the spell "could target", which is the original's targeting, and the Ink-Treader Nephilim and Mirrorwing Dragon rulings say so explicitly. 707.10e speaks of "the copy’s targets", and Beamsplitter Mage's ruling makes the copy's own legality decide whether it's created. Each card's ruling is followed. It was provisional because the CR uses identical words in both rules and a judge could read them alike.
- Affects: 707.10d: Ink-Treader Nephilim, Precursor Golem, Mirrorwing Dragon, Zada, Hedron Grinder, Radiate, Radiant Performer, Glimmervoid Basin, Agrus Kos, Eternal Soldier. 707.10e: Beamsplitter Mage, Frontline Heroism, Ivy, Gleeful Spellthief, Feather, Radiant Arbiter, Exterminator Magmarch, Zevlor, Elturel Exile, Blue Ribbon.
- Code: `crates/mtg-engine/src/copy_rules.rs` (`copy_for_each_target`, `copy_with_target`, `copy_targeting`).
- Tests: `tests/rulings/r_p028_copy_for_each.rs` (`ink_treader_nephilim_s_copies_use_the_original_spell_s_perspective_and_then_fizzle`), `tests/rulings/r_p029_triggers.rs` (`beamsplitter_mage_s_copy_isnt_created_if_it_cant_target_the_chosen_creature`).

## copied-chapter-ability-keeps-saga: A copy of a Saga's chapter ability keeps the Saga on the battlefield until the copy leaves the stack
- Kind: interpretation
- Status: decided
- Rules: 704.5s "If the number of lore counters on a Saga permanent with one or more chapter abilities is greater than or equal to its final chapter number and it isn’t the source of a chapter ability that has triggered but not yet left the stack, that Saga’s controller sacrifices it." / 707.10 "A copy of a spell or ability copies both the characteristics of the spell or ability and all decisions made for it ... A copy of an ability is itself an ability." / 707.10b "A copy of an ability has the same source as the original ability."
- Question: A Saga's final chapter ability triggers; Strionic Resonator copies it; the chapter ability that triggered is then countered (Stifle), leaving only the copy on the stack. Is the Saga "the source of a chapter ability that has triggered but not yet left the stack"? The copy is a chapter ability whose source is the Saga, but the copy itself never triggered.
- Decision: Decided by the user, Nov 12 (as recommended). Yes: a copy of a chapter ability counts as a chapter ability waiting on the stack, so the Saga isn't sacrificed until the copy has left the stack too. The same holds for a Siege (704.5v, any ability it's the source of) and a dungeon's room abilities (704.5t).
- Alternatives: Count only the chapter ability that actually triggered: the Saga would be sacrificed while the copy is still on the stack (it would still resolve, its source as it last existed).
- Why: The clause exists so the Saga's last chapter can do its work before the Saga goes; a copy of that ability has the Saga as its source (707.10b) and is the same ability in every other respect (707.10), and the rule's "that has triggered but not yet left the stack" reads naturally as "waiting to resolve". No ruling covers a copy. Provisional because the words "has triggered" can be read as excluding a copy.
- Affects: copies of chapter, Siege and room abilities (Strionic Resonator, Lithoform Engine) whose original leaves the stack first (rare: the copy is put above the original).
- Code: `crates/mtg-engine/src/sba.rs` (`is_source_of_stack_trigger_where`: a copy of a triggered ability is a `StackKind::Triggered` with the same source and ability).
- Tests: `tests/cr/r704_audit_sources.rs` (`a_copy_of_a_chapter_ability_keeps_its_saga_until_it_leaves_the_stack`).

## copy-for-each-one-copy-event: One instruction's copies of a spell are one copy event, also when it copies the spell "for each" of several objects or players
- Kind: interpretation
- Status: decided
- Rules: 608.2f "Some spells and abilities include actions taken on multiple players and/or objects. In most cases, each such action is processed simultaneously. If the action can’t be processed simultaneously, it’s instead processed considering each affected player or object individually. ..." and its first example, "Blatant Thievery says “For each opponent, gain control of target permanent that player controls.” As Blatant Thievery resolves, its controller gains control of all permanents chosen as targets simultaneously." (both since the CR effective 2020-11-20) / 700.1 "Anything that happens in a game is an event. Multiple events may take place during the resolution of a spell or ability. The text of triggered abilities and replacement effects defines the event they’re looking for. One “happening” may be treated as a single event by one ability and as multiple events by another." / 614.5 "A replacement effect doesn’t invoke itself repeatedly; it gets only one opportunity to affect an event or any modified events that may replace that event." / 707.10 "To copy a spell, activated ability, or triggered ability means to put a copy of it onto the stack; ..." / 707.10d "Some effects copy a spell or ability for each player or object it “could target.” The copies are put onto the stack with those targets in the order of their controller’s choice. ..." / 405.3 "If an effect puts two or more objects on the stack at the same time, ... If a player controls more than one of these objects, that player chooses their relative order on the stack." / Twinning Staff (Oracle): "If you would copy a spell one or more times, instead copy it that many times plus an additional time. You may choose new targets for the additional copy." Its rulings (2020-04-17; in the Ikoria: Lair of Behemoths and Commander (2020 Edition) Release Notes, Eli Shiffrin, 2020-04-10): "You choose whether the additional copy is put onto the stack before or after the original copy. If a spell is being copied more than once, you can even have the additional copy put onto the stack in between the original copies." / "You may choose new targets for the additional copy, even if you can't choose new targets for the original copy or copies." / Feather, Radiant Arbiter (Oracle, in part): "If you do, for each of those creatures, copy that spell. The copy targets that creature." Ruling (2024-02-02): "You control all the copies, and you choose the order the copies are put on the stack. The original spell will be on the stack beneath those copies and will resolve last." Zada, Hedron Grinder's ruling (2018-03-16) says the same, for "copy that spell for each other creature you control that the spell could target" (CR 707.10d): "You control all the copies. You choose the order the copies are put onto the stack. The original spell will be on the stack beneath those copies and will resolve last." / Zevlor, Elturel Exile (Oracle, in part): "for each other opponent, choose that player or a permanent they control, copy that spell, and the copy targets the chosen player or permanent." Ruling (2022-06-10; in the Commander Legends: Battle for Baldur's Gate Release Notes, Jess Dunks, 2022-06-01): "When the delayed triggered ability of Zevlor, Elturel Exile resolves, it may create one or more copies of a spell. You control each of the copies. ..." / Other "for each" instructions: Culmination of Studies ("For each red card exiled this way, Culmination of Studies deals 1 damage to each opponent."), ruling (2021-04-16; in the Strixhaven: School of Mages and Commander (2021 Edition) Release Notes, Jess Dunks and Matt Tabak, 2021-04-16): "If multiple red cards are exiled, all of the damage is dealt as a single event." Tempting Contract ("For each opponent who does, you create a Treasure token."), ruling (2021-04-16, the same release notes): "Each opponent in turn order decides whether or not to create a Treasure token. They will each know the decisions of players before them. Those Treasure tokens are all created at the same time. Then you create your Treasure tokens all at the same time." Suffer the Past ("For each card exiled this way, that player loses 1 life and you gain 1 life."), ruling (2010-06-15): "Suffer the Past’s effect causes a single life-gain event, not a number of separate ones. This matters for cards such as Cradle of Vitality." Wurmquake ("Then for each opponent with three or more poison counters, you create another one of those tokens."), ruling (2023-02-04): "The first token that Wurmquake creates as it resolves is created and enters the battlefield before the rest of them, then you create a number of tokens equal to the number of opponents with three of more poison counters and they enter the battlefield at the same time." Myriad (702.116a: "... for each opponent other than defending player, you may create a token that’s a copy of this creature that’s tapped and attacking that player or a planeswalker they control. ..."): Tabaxi Toucaneers ruling (2022-06-10; in the same release notes as Zevlor's): "The tokens all enter the battlefield at the same time."; Scurry of Squirrels ruling (2024-07-26): "The tokens created by a single instance of myriad all enter at the same time." / Additive "one or more" replacements and an instruction that does something several times: Heron of Hope ("If you would gain life, you gain that much life plus 1 instead."), ruling (2021-11-19): "... If you gain an amount of life "for each" of something or "equal to the number" of something, that life is gained as one event and the ability of Heron of Hope applies only once." (the same for Angel of Vitality, 2024-11-08, and Pest Rescuer, 2026-03-20). Quantum Riddler ("if you would draw one or more cards, you draw that many cards plus one instead"), ruling (2025-07-25): "If an effect instructs you to draw more than one card, Quantum Riddler’s replacement effect applies to that entire instruction, not the individual card draws represented by the instruction. ..." Vizier of Remedies ("If one or more -1/-1 counters would be put on a creature you control, that many -1/-1 counters minus one are put on it instead."), ruling (2017-04-18): "If multiple creatures with wither and/or infect deal damage to a creature at once, Vizier of Remedies causes only one counter fewer to be put on that creature. Its effect doesn’t apply separately for each creature dealing damage." / Read the other way: the tempting offer rulings for "For each opponent who does, [the effect]" (Tempt with Vengeance and the cycle, 2013-10-17, Commander 2013 Edition Release Notes, 2013-10-22, which call it letting opponents "also enjoy that effect if they allow you to repeat it"; Tempt with Bunnies, 2024-07-26): "After each opponent has decided, the effect happens simultaneously for each one who accepted the offer. Then, the effect happens again for you a number of times equal to the number of opponents who accepted." Winding Constrictor ruling (2017-02-09): "If an effect includes multiple instructions to put one or more counters on an artifact or creature, such as Lifecrafter's Gift does, Winding Constrictor's effect applies to each of those instructions." Rottenmouth Viper ("Then for each blight counter on it, each opponent loses 4 life unless that player sacrifices a nonland permanent of their choice or discards a card."), ruling (2024-07-26): "... Finally, that player discards the chosen cards, sacrifices the chosen permanents, and loses 4 life the appropriate number of times." Tamiyo Meets the Story Circle ("investigate twice for each card discarded this way"), ruling (2024-06-07): "If you're instructed to investigate multiple times, those actions are sequential, meaning you'll create that many Clue tokens one at a time."
- Question: An instruction that copies a spell once for each of several objects or players ("for each of those creatures, copy that spell. The copy targets that creature.", Feather; "for each other opponent, ..., copy that spell", Zevlor) copies it N times. Is that one event of copying the spell N times, which Twinning Staff makes N + 1 copies, or N events of copying it once, each made 2 (2N)? "Copy it twice", "copy it X times" and "copy it for each ..." (storm, replicate, CR 707.10d) are one instruction copying the spell several times, and no ruling or rule speaks to the "for each ..., copy" form.
- Decision: Decided by the user, Nov 19. One event. The copies one instruction makes of one spell for one player are one copy event, however it's worded, and Twinning Staff adds one copy to it (one for each Staff). Feather with two creatures chosen makes three copies with one Staff, four with two; Zevlor with two other opponents makes three with one Staff. Copies that different players make are their own events (Hive Mind, demonstrate, tempting offer: each player is a different "you"), as are copies of different spells and copies made by separate instructions or abilities (two storm triggers).
- Alternatives: N events (the engine's earlier behavior for Feather and Zevlor): each pass of the "for each" copies the spell once and gets Twinning Staff's copy, so 2N copies (N times (1 + k) with k Staffs), while "copy it twice" and the 707.10d cards still give N + k: the count would depend on the wording.
- Why: Not decided by any source: no ruling or rule names Twinning Staff with a "for each ..., copy" instruction (work item ruling-conflicts-11, conclusion D, recommending this reading). For it: 608.2f performs an action on several objects or players for all of them at once unless it can't be (its example: Blatant Thievery's "For each opponent, gain control of target permanent that player controls" gains control of them all "simultaneously"), and copying can be (707.10d's copies are put onto the stack together, in the order their controller chooses, and Feather's ruling says the same of its "for each" copies as Zada's, a 707.10d card, says of its copies); Twinning Staff's text defines its event as copying a spell "one or more times" (700.1), and one happening that copies a spell several times gets one opportunity to be modified (614.5); its ruling, too, gives "a spell ... being copied more than once" one "additional copy", which may go "in between the original copies"; rulings treat other "for each" instructions as one event, or as done at once (Culmination of Studies, Tempting Contract, both 2021, after 608.2f; Suffer the Past's "For each card exiled this way, that player loses 1 life and you gain 1 life", 2010, "a single life-gain event, not a number of separate ones"; Wurmquake's "for each opponent ..., you create another one of those tokens", 2023, read as creating "a number of tokens equal to the number of opponents" that enter "at the same time"; myriad's "for each opponent ..., you may create a token", whose tokens "all enter the battlefield at the same time", in the same release notes as Zevlor's "for each other opponent"), and apply additive "one or more" replacements once to an instruction that does something several times (Heron of Hope, Angel of Vitality, Pest Rescuer, Quantum Riddler) or to what several sources do at once (Vizier of Remedies; split by the player putting the counters, `damage-counters-put-by-different-players-are-separate-events`, as copies are split here by the player copying; see also `entering-counters-one-event`). Against it: the tempting offer rulings (2013, before 608.2f; reused in 2024) have the effect happen "again for you a number of times", which can be read as separate repetitions, though they don't say the times are separate events (Tempting Contract's ruling has the same "for each opponent who does" create your tokens "all at the same time"); Winding Constrictor's ruling counts instructions, and a "for each" instruction is one; the per-pass wording ("copy that spell. The copy targets that creature.") can be read as one copying per object; Rottenmouth Viper's ruling (2024) has the life loss of its "for each" passes happen "the appropriate number of times" (in a multiplayer game "all of the actions occur simultaneously", its other ruling says); and a repeated keyword action is sequential (investigate: Tamiyo Meets the Story Circle, 2024), though copying isn't a keyword action, and Twinning Staff's own text and ruling make "copy it twice" one copying. A judge could rule 2N, so the user reviews it. The same reading for tokens, counters and life gained "for each" of several objects or players is `for-each-tokens-counters-life-one-event` (small-fixes-3, Nov 20).
- Affects: Twinning Staff with Feather, Radiant Arbiter and Zevlor, Elturel Exile, the only cards that copy a spell "for each" of several objects or players in one instruction (Mizzix's Mastery's "For each card exiled this way, copy it" copies cards, which Twinning Staff doesn't change). Unchanged: storm, replicate, gravestorm, "copy it twice" and "copy it X times", 707.10d's "for each ... it could target" (Zada, Radiate, Ink-Treader Nephilim), and each player's own copies (Hive Mind, Tempt with Mayhem, Curse of Echoes, demonstrate).
- Code: `crates/mtg-engine/src/copy.rs` (`additional_copies`, `begin_copy_event`, `end_copy_event`); `crates/mtg-engine/src/resolve.rs` (`Effect::ForEach` whose body copies a spell); `crates/mtg-engine/src/kw/choices_5_filters.rs` (`ORDER_COPIES_MADE`, Zevlor's copies); `crates/mtg-engine/src/kw/keyword_state.rs` (`KeywordState::copy_event`). Only these two shapes open the event, and they're all the card pool has (every card's compiled abilities scanned for a spell copy inside a per-object or per-player loop, in the review of ruling-conflicts-11: Feather's `ForEach` of `CopySpellRetargeted`, Zevlor's custom pair, and each player's own copies for Tempt with Mayhem and Curse of Echoes); a new card that copies a spell for each of several objects in another shape (a loop whose body has other instructions too, or a nested loop) needs the same.
- Tests: `tests/rulings/copy_event_for_each.rs` (`feathers_copies_for_each_creature_are_one_copy_event`, `zevlors_copies_for_each_other_opponent_are_one_copy_event`, `copying_a_spell_twice_is_one_copy_event`, `separate_copy_instructions_are_separate_copy_events`).

## copy-of-a-card-that-left-is-made-where-it-was: A copy of a card that has left the zone it was in is created in that zone, from its last known information
- Kind: interpretation
- Status: provisional
- Rules: 707.12 "An effect that instructs a player to cast a copy of an object (and not just copy a spell) follows the rules for casting spells, except that the copy is created in the same zone the object is in and then cast while another spell or ability is resolving. ..." / 608.2h "... If the effect requires information from a specific object, including the source of the ability itself, the effect uses the current information of that object if it’s in the public zone it was expected to be in; if it’s no longer in that zone, or if the effect has moved it from a public zone to a hidden zone, the effect uses the object’s last known information. ..." / God-Eternal Kefnet rulings (2019-05-03): "If the card leaves your hand before Kefnet's triggered ability resolves, you'll copy it using its last known information." and "The copy is created in and cast from your hand."
- Question: Kefnet's trigger copies the revealed card ("copy that card and you may cast the copy"). If the card has left the hand by the time the ability resolves, the copy is made from its last known information, but 707.12 creates the copy "in the same zone the object is in", and the object is no longer anywhere: which zone is the copy created in (and cast from)?
- Decision: The zone the card was in as it last existed there (for Kefnet, the hand): the copy is created there from the card's last known information and cast from there, as it would have been had the card stayed.
- Alternatives: (a) The zone the card has moved to (a graveyard after a discard): the copy would be cast from that graveyard, and effects that care where a spell was cast from would see it differently. (b) No copy at all once the card has left (against the first ruling).
- Why: The first ruling makes the copy from last known information, which includes the zone the card was in; the second says the copy is created in and cast from the hand, with no exception for a card that left. The card in its new zone is a new object (400.7), not the card the trigger refers to, so "the zone the object is in" is the zone in the revealed card's last known information. Provisional because neither ruling nor 707.12 says where the copy of a card that has left goes.
- Affects: "copy that card" in a trigger naming a card (God-Eternal Kefnet; 1 card).
