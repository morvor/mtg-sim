# Copy effects

Judgment calls about copiable values and copy effects (CR 707). Format and kinds:
`docs/agents/items/interpretation-register.md`; index: `docs/INTERPRETATIONS.md`.

## copy-exception-ability-stacks: An ability a copy exception grants is added again even when the copied values already have it
- Kind: interpretation
- Status: decided
- Rules: 707.9a "Some copy effects cause the copy to gain an ability as part of the copying process. This ability becomes part of the copiable values for the copy, along with any other abilities that were copied." / 707.3 "The copy’s copiable values become the copied information, as modified by the copy’s status (see rule 110.5). Objects that copy the object will use the new copiable values." / 113.2c "... If an object has multiple instances of the same ability, each instance functions independently. This may or may not produce more effects than a single instance; refer to the specific ability for more information." / Gigantoplasm ruling: "If the chosen creature is copying something else (for example, if the chosen creature is another Gigantoplasm), then Gigantoplasm enters the battlefield as whatever the chosen creature was copying (plus any abilities it gained as part of the copy process, if applicable)." / Phantasmal Image ruling: "The Illusion creature type and the triggered ability that Phantasmal Image gains as part of its copy effect are both copiable values that other effects may copy." / Vesuvan Doppelganger ruling: "A Vesuvan Doppelganger that becomes a copy of a Vesuvan Doppelganger (either itself or a different one) will gain another instance of its triggered ability."
- Question: When a copy effect's exception grants an ability ("except it has '{X}: This creature has base power and toughness X/X.'") and the copied values already contain that ability (the copied object is another Gigantoplasm), does the copy have it once or twice? The CR doesn't say it outright.
- Decision: Twice. The copied values (which include the first copy's gained ability, 707.9a) are copied, and then the exception adds its ability again; nothing merges identical abilities.
- Alternatives: Treat an exception's ability as not added when an identical one is already among the copied values (the copy has it once). For activated abilities like Gigantoplasm's this changes nothing visible; for triggered abilities (Vesuvan Doppelganger, Phantasmal Image's sacrifice trigger) it would halve the triggers.
- Why: 707.9a makes the gained ability part of the copiable values "along with any other abilities that were copied", 113.2c says multiple instances are independent, and the Vesuvan Doppelganger ruling says exactly this for a copy of a copy with the same exception. The Gigantoplasm ruling's "plus any abilities it gained as part of the copy process" points the same way: the second Gigantoplasm enters with the first one's gained ability and then gains its own. The judge audit (`docs/agents/reports/judge-audit-1.md`, rulings-18) agreed with medium confidence, noting that the CR doesn't say it outright; decided rather than provisional because the Vesuvan Doppelganger ruling settles the identical structure explicitly.
- Affects: copy effects with "except it has [ability]" copying an object that already gained that ability: for example Gigantoplasm, Vesuvan Doppelganger, Phantasmal Image and Cryptoplasm (count not measured).
- Code: `crates/mtg-engine/src/layers.rs` (layer 1, `Layer1::Copy`: exceptions applied on top of the copied values); `crates/mtg-engine/src/copy.rs` (`become_copy`, `add_copy_exceptions`).
- Tests: `tests/rulings/r_p023_enter_as_copy.rs` (`gigantoplasm_copying_another_gigantoplasm`, `phantasmal_image_copying_a_phantasmal_image_has_two_sacrifice_triggers`).

## copy-values-fixed-when-determined: A copy takes the copiable values the original has when the copy is determined
- Kind: interpretation
- Status: decided
- Rules: 707.2 "When copying an object, the copy acquires the copiable values of the original object’s characteristics ..." / 707.5 "An object that enters the battlefield “as a copy” or “that’s a copy” of another object becomes a copy as it enters the battlefield. It doesn’t enter the battlefield, and then become a copy of that permanent. If the text that’s being copied includes any abilities that replace the enters-the-battlefield event (such as “enters with” or “as [this] enters” abilities), those abilities will take effect. ..." / 614.12a "If a replacement effect that modifies how a permanent enters the battlefield requires a choice, that choice is made before the permanent enters the battlefield." / 707.2c "If a static ability generates a continuous effect that’s a copy effect, the copiable values that effect grants are determined only at the time that effect first starts to apply."
- Question: A copy's own copied "as this enters" ability can change the object it copies before the copy is on the battlefield: a token copy of Ixidron, or a Clone entering as a copy of Ixidron, turns "all other nontoken creatures" face down as it enters, the original Ixidron included. Does the copy copy Ixidron, or the face-down 2/2 the original has become?
- Decision: Decided by the user, Oct 28. Ixidron. A token "that's a copy of" an object takes the object's copiable values as the token is created; a permanent that enters as a copy of a chosen object takes them as the object is chosen (614.12a: before it enters). Effects applied as it enters don't change what it copies.
- Alternatives: Read the values as the copy effect starts to apply, when the permanent enters (707.2c's wording for static copy effects): the copy would then be a nameless face-down 2/2 whose copied ability it no longer has.
- Why: The copy effect is what gives the copy the "as this enters" ability that changes the original; letting that ability change what it copies is circular, and the token's characteristics are set by the effect that creates it. No ruling covers it; a judge could read 707.2c the other way for the Clone.
- Affects: copies of permanents with "as this enters" abilities that change other permanents (Ixidron; count not measured).
- Code: `crates/mtg-engine/src/replacement.rs` (`EtbInfo::copy_values`, `EtbInfo::copied_values`, set in `EnterAsCopy` and `AsEnters`); `crates/mtg-engine/src/actions.rs` (`token_entry`).
- Tests: `tests/cr/r707_009_copy_exceptions_and_values.rs` (`a_token_copy_copies_the_original_as_it_was_when_the_token_was_created`, `a_clone_copies_the_chosen_object_as_it_was_chosen`).

## copy-target-legality-original-or-copy: Copies made for each object a spell "could target" are decided from the original spell's point of view; a copy given a specified target is created only if the copy itself can target it
- Kind: interpretation
- Status: decided
- Rules: 707.10d "Some effects copy a spell or ability for each player or object it “could target.” The copies are put onto the stack with those targets in the order of their controller’s choice. If the spell or ability has more than one target, each of its targets must be the same player or object. If that player or object isn’t a legal target for each instance of the word “target,” a copy isn’t created for that player or object." / 707.10e "Some effects copy a spell or ability and specify a new target for the copy. If the spell or ability has more than one target, each of the copy’s targets must be that player or object. If that player or object isn’t a legal target for each instance of the word “target,” the copy isn’t created. ..." / 707.2 "When copying an object, the copy acquires the copiable values of the original object’s characteristics ..." / 608.2b "If the spell or ability specifies targets, it checks whether the targets are still legal. ..." Ink-Treader Nephilim's ruling (2006-02-01): "Even though you control the copies, the ability cares about who cast the original spell when determining which other creatures that spell could target. If the original spell has a targeting restriction that refers to "an opponent," the copies will see that from the perspective of the original spell's controller. For example, if your opponent casts a spell that says "Destroy target creature an opponent controls" targeting your Ink-Treader Nephilim, its ability will create a copy for each other creature the original spell could target: the rest of your creatures. However, since you control the copies, all the copies won't resolve for having illegal targets." Mirrorwing Dragon's ruling (2016-07-13): "Any creature the player controls that couldn't be targeted by the original spell (due to shroud, protection abilities, targeting restrictions, or any other reason) is just ignored by Mirrorwing Dragon's ability. If the spell has multiple targets, a given creature must be a legal target for all of them or else a copy won't be created for that creature." Beamsplitter Mage's ruling (2018-10-05): "In some rare cases, the original spell can target another creature but the copy can’t (most likely because an effect modified the characteristics of the original spell on the stack and won’t modify the copy). If the copy can’t target the chosen creature, the copy isn’t created." Ivy, Gleeful Spellthief's ruling (2022-09-09): "If Ivy, Gleeful Spellthief isn't a legal target for the spell, no copy can be created." Zevlor, Elturel Exile's ruling (2022-06-10): "... but if the chosen player or permanent isn't a legal target for the spell, the copy won't be created."
- Question: 707.10d and 707.10e end with the same words: if "that player or object isn’t a legal target for each instance of the word “target,”" the copy isn't created. A legal target for which spell: the original (cast by its controller, with its characteristics as they are on the stack), or the copy (controlled by whoever copies it, with only the original's copiable values, 707.2)? The two differ when the copy has another controller (Ink-Treader Nephilim copies an opponent's spell) or when an effect changed the original on the stack (Blind Seer made it another color).
- Decision: Decided by the user, Nov 5. A copy made "for each [object or player] that spell could target" (707.10d) is decided from the original spell's point of view: one copy for each object or player the original could target, even one the copy itself can't target; that copy is put onto the stack targeting it and, if its target is illegal as it resolves, it doesn't resolve (608.2b). A copy whose new target an effect specifies (707.10e: "Copy that spell. The copy targets the chosen creature.") is created only if that object or player is a legal target both for the original spell (the choices offered; Ivy's and Zevlor's "a legal target for the spell") and for the copy itself as it's put onto the stack (Beamsplitter Mage's ruling). Otherwise the copy isn't created: it never was on the stack, so nothing sees it being copied or becoming a target ("whenever you copy a spell" doesn't trigger).
- Alternatives: (a) The copy's point of view in both: Ink-Treader Nephilim would make no copies of an opponent's "destroy target creature an opponent controls" (its ruling says it makes them and they don't resolve), and the copies Mirrorwing Dragon's ruling describes would be decided by the copy. (b) The original's point of view in both: Beamsplitter Mage's copy would be created targeting a creature it can't target and be countered as it resolves, against its ruling, and "whenever you copy a spell" abilities would trigger for it. (c) For 707.10e, the copy's legality only: a copy could then target an object the original couldn't (Ivy's copy of an opponent's "target creature you control" spell targeting Ivy), against Ivy's and Zevlor's rulings read as speaking of the original.
- Why: 707.10d defines the copies by what the spell "could target", which is the original's targeting, and the Ink-Treader Nephilim and Mirrorwing Dragon rulings say so explicitly. 707.10e speaks of "the copy’s targets", and Beamsplitter Mage's ruling makes the copy's own legality decide whether it's created. Each card's ruling is followed. It was provisional because the CR uses identical words in both rules and a judge could read them alike.
- Affects: 707.10d: Ink-Treader Nephilim, Precursor Golem, Mirrorwing Dragon, Zada, Hedron Grinder, Radiate, Radiant Performer, Glimmervoid Basin, Agrus Kos, Eternal Soldier. 707.10e: Beamsplitter Mage, Frontline Heroism, Ivy, Gleeful Spellthief, Feather, Radiant Arbiter, Exterminator Magmarch, Zevlor, Elturel Exile, Blue Ribbon.
- Code: `crates/mtg-engine/src/copy_rules.rs` (`copy_for_each_target`, `copy_with_target`, `copy_targeting`).
- Tests: `tests/rulings/r_p028_copy_for_each.rs` (`ink_treader_nephilim_s_copies_use_the_original_spell_s_perspective_and_then_fizzle`), `tests/rulings/r_p029_triggers.rs` (`beamsplitter_mage_s_copy_isnt_created_if_it_cant_target_the_chosen_creature`).

## copied-chapter-ability-keeps-saga: A copy of a Saga's chapter ability keeps the Saga on the battlefield until the copy leaves the stack
- Kind: interpretation
- Status: provisional
- Rules: 704.5s "If the number of lore counters on a Saga permanent with one or more chapter abilities is greater than or equal to its final chapter number and it isn’t the source of a chapter ability that has triggered but not yet left the stack, that Saga’s controller sacrifices it." / 707.10 "A copy of a spell or ability copies both the characteristics of the spell or ability and all decisions made for it ... A copy of an ability is itself an ability." / 707.10b "A copy of an ability has the same source as the original ability."
- Question: A Saga's final chapter ability triggers; Strionic Resonator copies it; the chapter ability that triggered is then countered (Stifle), leaving only the copy on the stack. Is the Saga "the source of a chapter ability that has triggered but not yet left the stack"? The copy is a chapter ability whose source is the Saga, but the copy itself never triggered.
- Decision: Yes: a copy of a chapter ability counts as a chapter ability waiting on the stack, so the Saga isn't sacrificed until the copy has left the stack too. The same holds for a Siege (704.5v, any ability it's the source of) and a dungeon's room abilities (704.5t).
- Alternatives: Count only the chapter ability that actually triggered: the Saga would be sacrificed while the copy is still on the stack (it would still resolve, its source as it last existed).
- Why: The clause exists so the Saga's last chapter can do its work before the Saga goes; a copy of that ability has the Saga as its source (707.10b) and is the same ability in every other respect (707.10), and the rule's "that has triggered but not yet left the stack" reads naturally as "waiting to resolve". No ruling covers a copy. Provisional because the words "has triggered" can be read as excluding a copy.
- Affects: copies of chapter, Siege and room abilities (Strionic Resonator, Lithoform Engine) whose original leaves the stack first (rare: the copy is put above the original).
- Code: `crates/mtg-engine/src/sba.rs` (`is_source_of_stack_trigger_where`: a copy of a triggered ability is a `StackKind::Triggered` with the same source and ability).
- Tests: `tests/cr/r704_audit_sources.rs` (`a_copy_of_a_chapter_ability_keeps_its_saga_until_it_leaves_the_stack`).
