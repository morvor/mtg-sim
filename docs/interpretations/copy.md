# Copy effects

Judgment calls about copiable values and copy effects (CR 707). Format and kinds:
`docs/agents/items/interpretation-register.md`; index: `docs/INTERPRETATIONS.md`.

## copy-exception-ability-stacks: An ability a copy exception grants is added again even when the copied values already have it
- Kind: interpretation
- Status: decided
- Rules: 707.9a "Some copy effects cause the copy to gain an ability as part of the copying process. This ability becomes part of the copiable values for the copy, along with any other abilities that were copied." / 707.3 "The copy’s copiable values become the copied information, as modified by the copy’s status (see rule 110.5). Objects that copy the object will use the new copiable values." / 113.2c "... If an object has multiple instances of the same ability, each instance functions independently. This may or may not produce more effects than a single instance; refer to the specific ability for more information." / Gigantoplasm ruling: "If the chosen creature is copying something else (for example, if the chosen creature is another Gigantoplasm), then Gigantoplasm enters the battlefield as whatever the chosen creature was copying (plus any abilities it gained as part of the copy process, if applicable)." / Phantasmal Image ruling: "The Illusion creature type and the triggered ability that Phantasmal Image gains as part of its copy effect are both copiable values that other effects may copy." / Vesuvan Doppelganger ruling: "A Vesuvan Doppelganger that becomes a copy of a Vesuvan Doppelganger (either itself or a different one) will gain another instance of its triggered ability."
- Question: When a copy effect's exception grants an ability ("except it has '{X}: This creature has base power and toughness X/X.'") and the copied values already contain that ability (the copied object is another Gigantoplasm), does the copy have it once or twice? The CR doesn't say it outright.
- Decision: Twice. The copied values (which include the first copy's gained ability, 707.9a) are copied, and then the exception adds its ability again; nothing merges identical abilities.
- Alternatives: Treat an exception's ability as not added when an identical one is already among the copied values (the copy has it once). For activated abilities like Gigantoplasm's this changes nothing visible; for triggered abilities (Vesuvan Doppelganger, Phantasmal Image's sacrifice trigger) it would halve the triggers.
- Why: 707.9a makes the gained ability part of the copiable values "along with any other abilities that were copied", 113.2c says multiple instances are independent, and the Vesuvan Doppelganger ruling says exactly this for a copy of a copy with the same exception. The Gigantoplasm ruling's "plus any abilities it gained as part of the copy process" points the same way: the second Gigantoplasm enters with the first one's gained ability and then gains its own. The judge audit (`docs/agents/reports/judge-audit-1.md`, rulings-18) agreed with medium confidence, noting that the CR doesn't say it outright; decided rather than provisional because the Vesuvan Doppelganger ruling settles the identical structure explicitly.
- Affects: copy effects with "except it has [ability]" copying an object that already gained that ability: for example Gigantoplasm, Vesuvan Doppelganger, Phantasmal Image and Cryptoplasm (count not measured).
- Code: `crates/mtg-engine/src/layers.rs` (layer 1, `Layer1::Copy`: exceptions applied on top of the copied values); `crates/mtg-engine/src/copy.rs` (`become_copy`, `add_copy_exceptions`).
- Tests: `tests/rulings/r_p023_enter_as_copy.rs` (`gigantoplasm_copying_another_gigantoplasm`, `phantasmal_image_copying_a_phantasmal_image_has_two_sacrifice_triggers`).
