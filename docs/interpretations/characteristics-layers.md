## changeling-cda-only: Only changeling's characteristic-defining ability makes an object every creature type
- Kind: interpretation
- Status: decided
- Rules: 702.73a "Changeling is a characteristic-defining ability. “Changeling” means “This object is every creature type.” This ability works everywhere, even outside the game. See rule 604.3." / 604.3a "A static ability is a characteristic-defining ability if it meets the following criteria: (1) It defines an object’s colors, subtypes, power, or toughness; (2) it is printed on the card it affects, it was granted to the token it affects by the effect that created the token, or it was acquired by the object it affects as the result of a copy effect or text-changing effect; (3) it does not directly affect the characteristics of any other objects; (4) it is not an ability that an object grants to itself; and (5) it does not set the values of such characteristics only if certain conditions are met." / 613.1d "Layer 4: Type-changing effects are applied. These include effects that change an object’s card type, subtype, and/or supertype." / 613.1f "Layer 6: Ability-adding effects, keyword counters, ability-removing effects, and effects that say an object can’t have an ability are applied." / 613.3 "Within layers 2–6, apply effects from characteristic-defining abilities first (see rule 604.3), then all other effects in timestamp order (see rule 613.7). ..."
- Question: Is an object that gains the changeling keyword from an effect other than token creation, a copy effect or a text-changing effect every creature type? 702.73a calls changeling a characteristic-defining ability, but under 604.3a(2) such a granted instance isn't one, and the CR never says how an ability added in layer 6 would change types in layer 4.
- Decision: No (option B, decided by the coordinator on Oct 14). Only the characteristic-defining ability, which sets the layer-4 flag `all_creature_types`, makes an object every creature type. A printed changeling, changeling granted to a token by the effect creating it ("create a ... token with changeling") and changeling acquired through a copy effect come with that ability; a changeling keyword granted any other way is just a keyword. Every reader (filters "a Goblin", shared creature types, prowl, mana spend restrictions, party, type counts) goes through the one flag.
- Alternatives: (A) The keyword confers every creature type wherever it comes from: matches the evident intent of a card that grants changeling, but no rule text supports it and every reader would have to look at the keyword too. (C) Model a granted changeling as a non-characteristic-defining static ability with its own layer-4 effect and timestamp (613.7a): needs layer 4 to apply an ability that only exists after layer 6, which the CR doesn't describe.
- Why: 604.3a(2) says the granted ability isn't characteristic-defining, 613.1 applies layer 4 before layer 6, and 613.8 dependencies work only within one layer, so nothing applies a layer-6 grant back in layer 4. The reasoning and the card survey are in `docs/agents/reports/structure-tests.md` section 4.
- Affects: no supported card that is legal in some format behaves differently under A, B or C today. The cards granting the bare keyword (Everyone's an Imposter, Oddric, Lunar Marquis, Brigid) are legal in no format; token creators (Birthing Boughs, Stalactite Dagger, Crib Swap, Formless Genesis, ...) and copy exceptions (Omni-Changeling, Moritte of the Frost) get the characteristic-defining ability.
- Code: `crates/mtg-engine/src/kw/changeling.rs` (`every_creature_type`, `changeling_cda`); `crates/mtg-engine/src/eval.rs` (`Filter::Subtype` reads `Characteristics::has_subtype`); `crates/mtg-engine/src/oracle/keywords.rs` (`compile_keyword` adds the characteristic-defining ability to a printed changeling and to a token "with changeling").
- Tests: `tests/keywords/k702_073_changeling.rs` (`a_creature_given_changeling_by_an_effect_is_not_every_creature_type`, `changeling_acquired_through_token_creation_or_a_copy_effect_is_every_creature_type`); `tests/cards/structure_triggered_9.rs` (`stalactite_dagger_creates_a_changeling_shapeshifter`); `tests/cards/structure_activated_10.rs` (`birthing_boughs_makes_a_changeling_shapeshifter`, Birthing Boughs and Ovinize).

## commander-identity-protection-player: "Protection from each color that's not in your commander's color identity" uses the protected permanent's controller's commanders
- Kind: interpretation
- Status: decided
- Rules: 903.4f "If an ability refers to the colors or number of colors in a commander’s color identity, that quality is undefined if that player doesn’t have a commander. That part of the ability won’t do anything. ..." / 702.16a "Protection is an evasion ability that ..."
- Question: Commander's Plate grants the equipped creature protection based on "your commander's color identity". If the Equipment's controller and the creature's controller differ (an Equipment attached to another player's creature), whose commander is it?
- Decision: The color identity of the commanders of the protected permanent's controller (the player for whom the protection ability is evaluated); none (no protection) if that player has no commander. With two commanders, their combined identity (its rulings).
- Alternatives: The Equipment's controller's commander.
- Why: Protection abilities are evaluated for the permanent that has them; the two players are the same whenever Commander's Plate is equipped by its own ability, the usual case.
- Affects: Commander's Plate.
- Code: `crates/mtg-engine/src/kw/game_rules_4.rs` (`COLOR_OUTSIDE_COMMANDER_IDENTITY`); `crates/mtg-engine/src/stack.rs` (`protected_from`).
- Tests: `tests/cards/game_rules_4.rs` (`commanders_plate_protects_from_colors_outside_the_commanders_identity`).

## conditional-pt-setting-not-cda: "During your turn, ~'s power and toughness are each ... During turns other than yours, ... each 2" sets power and toughness in layer 7b on the battlefield
- Kind: interpretation
- Status: decided
- Rules: 604.3a "A static ability is a characteristic-defining ability if it meets the following criteria: ... and (5) it does not set the values of such characteristics only if certain conditions are met." / 613.4a "Layer 7a: Effects from characteristic-defining abilities that define power and/or toughness are applied." / 613.4b "Layer 7b: Effects that set power and/or toughness to a specific number or value are applied."
- Question: Angry Mob (printed 2+*/2+*) says "During your turn, Angry Mob's power and toughness are each equal to 2 plus the number of Swamps your opponents control. During turns other than yours, Angry Mob's power and toughness are each 2." Each sentence sets the values only if a condition is met (whose turn it is), but together they set them on every turn. Is that one characteristic-defining ability (layer 7a, every zone) or conditional setting effects (layer 7b, battlefield only)?
- Decision: Decided by the user, Nov 4. Conditional setting effects: two static abilities, each with its condition ("it's your turn" / "it isn't"), setting power and toughness in layer 7b while the creature is on the battlefield; elsewhere it has its printed 2+* with * as 0 (2/2). The same reading the engine already gives Gaea's Liege ("As long as ~ isn't attacking, ... As long as ~ is attacking, ...", `statics_cda::conditional_cda`).
- Alternatives: One characteristic-defining ability whose value depends on whose turn it is (layer 7a, in every zone): an earlier-timestamped "becomes 0/1" effect (layer 7b) would then override it instead of being overridden by it, and in other zones it would count opposing Swamps during your turn.
- Why: 604.3a(5) excludes abilities that set the values only if conditions are met, and each sentence of Angry Mob does exactly that; Gaea's Liege's paired conditions are compiled the same way, so both cards follow one rule. No Scryfall ruling addresses it.
- Affects: Angry Mob (and Gaea's Liege by the earlier pattern).
- Code: `crates/mtg-engine/src/oracle/patterns/paper_statics.rs` (`pt_during_your_turn`).
- Tests: `tests/cards/paper_statics.rs` (`angry_mob_counts_opposing_swamps_only_during_your_turn`).

## control-gain-prohibition-before-controller: "Other players can't gain control of [them]" stops changes of control away from the permanent's controller, judged as that player controls it
- Kind: interpretation
- Status: decided
- Rules: 613.1b "Layer 2: Control-changing effects are applied." / 611.3a "A continuous effect generated by a static ability isn’t “locked in”; it applies at any given moment to whatever its text indicates." Guardian Beast's ruling: "This does not stop sacrifices."
- Question: Guardian Beast says "As long as ~ is untapped, noncreature artifacts you control ... other players can't gain control of them." The CR has no rule for "can't gain control". When does it apply, and what happens to a control-changing effect that took hold while Guardian Beast was tapped once it untaps?
- Decision: Decided by the user, Nov 4. A control-changing effect (layer 2) doesn't give a permanent to a player when the prohibition applies to it as its controller before that change sees it: the prohibition's controller controlled it, it matches "noncreature artifacts you control" with that controller, and the new controller is another player. A permanent another player already controls (because the effect began while the prohibition didn't apply) stays with that player when the prohibition applies again. Sacrifices, destruction and other events are unaffected.
- Alternatives: (A) Re-evaluate in every layer pass whether the original owner would control it without the effect, which would hand the artifact back as soon as Guardian Beast untaps, as though the opponent's effect stopped; (B) apply the prohibition only as a control-changing effect begins (an Aura's static "you control enchanted artifact" never "begins" in that sense, so it would never be stopped).
- Why: "can't gain control" is about the event of gaining control; once a player has gained control, nothing in the text undoes it, and a continuous re-check (A) would make control flip back and forth with Guardian Beast's tapped state. Reading the "you control" of the protected group with the controller from before the change keeps the protection from depending on the change it is meant to stop.
- Affects: Guardian Beast.
- Code: `crates/mtg-engine/src/layers.rs` (`apply_mod_to`, `CONTROL_BEFORE`); `crates/mtg-engine/src/prohibitions.rs` (`control_gain_prohibited`).
- Tests: `tests/cards/paper_statics.rs` (`guardian_beast_stops_other_players_gaining_control_but_not_sacrifices`, `guardian_beast_does_nothing_while_tapped_and_leaves_auras_attached`).

## full-text-undefined-mana-cost: An object given the "full text" of a card with no mana cost keeps its own mana cost, and its color comes from that mana cost and the card's color indicator
- Kind: interpretation
- Status: decided
- Rules: 612.6 "One card (Volrath’s Shapeshifter) states that an object has the “full text” of another object. This changes not just the text that appears in the object’s text box and type line, but also changes the text that represents its name, mana cost, color indicator, power, and toughness." / 202.2 "An object is the color or colors of the mana symbols in its mana cost, regardless of the color of its frame." / 202.2e "An object may have a color indicator printed to the left of the type line. That object is each color denoted by that color indicator." / Volrath's Shapeshifter rulings (2004-10-04): "If the top card in the graveyard has any other undefined characteristics, then those characteristics are not acquired and the shapeshifter uses the characteristic from its own card." and "If the top card in your graveyard is a creature card, this card uses the listed characteristics, including color and any other types."
- Question: Volrath's Shapeshifter ({1}{U}{U}) with a creature card that has no mana cost on top of the graveyard (Dryad Arbor, green by its color indicator): the first ruling keeps the Shapeshifter's own mana cost, but what color is it?
- Decision: Decided by the user, Nov 5. It keeps {1}{U}{U} (mana value 3) and takes the card's color indicator, so it's the colors of both: blue (its mana cost, 202.2) and green (the indicator, 202.2e).
- Alternatives: (A) Only the card's colors (green): the second ruling ("uses the listed characteristics, including color") and the reminder text ("This creature has that card's name, mana cost, color, ...") can be read as giving it the card's color outright; but 612.6 lists what the full text replaces (name, mana cost, color indicator, power, toughness and the text box and type line), color isn't among them, and color is derived from the mana cost and color indicator the object then has (202.2, 202.2e); for every card with a mana cost the two readings agree. (B) Only blue, ignoring the indicator: but 612.6 says the color indicator is taken.
- Why: 612.6 replaces the text of the mana cost and the color indicator; the first ruling says a characteristic the card doesn't define isn't acquired, so the Shapeshifter's mana cost text stays, and 202.2 and 202.2e derive color from the mana cost and the color indicator it then has. A judge could read the second ruling and the reminder text as (A), which is why it was provisional.
- Affects: Volrath's Shapeshifter (and copies of it) with a creature card with no mana cost on top of the graveyard: Dryad Arbor (green indicator) and Asmoranomardicadaistinaculdacar (black and red indicator). Cards with a mana cost are unaffected.
- Code: `crates/mtg-engine/src/text_change.rs` (`take_full_text`).
- Tests: `tests/rulings/r_p024_misc.rs` (`volraths_shapeshifter_keeps_its_own_undefined_characteristics`).

## name-setting-in-layer-3: An effect that sets a permanent's name applies in layer 3
- Kind: interpretation
- Status: decided
- Rules: 613.1c "Layer 3: Text-changing effects are applied. See rule 612, “Text-Changing Effects.”" / 612.8 "Some cards create a continuous effect that sets the name of an object. This changes the text that represents the object’s name. ..." / 613.1d "Layer 4: Type-changing effects are applied. These include effects that change an object’s card type, subtype, and/or supertype."
- Question: Psychic Paper says the equipped creature's "name and creature type are the last chosen name and creature type". No layer in 613.1 names an object's name; in which layer does a name-setting effect apply?
- Decision: Decided by the user, Nov 4. With the text-changing effects, in layer 3 (612.8 lists name changes in the text-changing rules), in timestamp order with them; the creature type part is a type-changing effect in layer 4 that replaces the creature's creature types with the chosen one. Each applies only once its choice was made (607.5a).
- Alternatives: Layer 1 (as a copiable value): would wrongly make the name copiable by copy effects, which copy only the copiable values the Equipment's effect doesn't set (707.2).
- Why: 612.8 puts name changes among the text-changing effects, which apply in layer 3; the engine's existing `Modification::SetName` already applies there.
- Affects: Psychic Paper.
- Code: `crates/mtg-engine/src/kw/attach_choices_5.rs` (`LAST_CHOSEN_NAME`, `LAST_CHOSEN_CREATURE_TYPE`).
- Tests: `tests/cards/cards5_choices_players.rs` (`psychic_paper_sets_the_equipped_creatures_name_and_creature_type`).

## room-door-unlock-timestamp: A Room door unlocked after the permanent entered has its static abilities' effects timestamped from the unlocking
- Kind: deviation
- Status: decided
- Rules: 613.7a "A continuous effect generated by a static ability has the same timestamp as the object the static ability is on, or the timestamp of the effect that created the ability, whichever is later. ..." / 613.7f "A permanent receives a new timestamp each time it turns face up or face down." / 613.7g "A double-faced permanent receives a new timestamp each time it transforms or converts." / 730.2a "... This is a copiable effect whose timestamp is the time the objects merged. ..." / 709.5 "... These are “As long as this permanent doesn’t have the ‘left half unlocked’ designation, it doesn’t have the name, mana cost, or rules text of this object’s left half” ... These abilities, as well as which half of that permanent a characteristic is in, are part of that object’s copiable values." / 709.5e "A player who controls a permanent that has one or more locked halves may pay the mana cost of a locked half of that permanent to give that permanent the appropriate unlocked designation. ..." / Roaring Furnace // Steaming Sauna ruling (2024-09-20): "If multiple effects modify your hand size, apply them in timestamp order. For example, if you unlock Steaming Sauna and then put Null Profusion (an enchantment that says your maximum hand size is two) onto the battlefield, your maximum hand size would be two. However, if Null Profusion entered first and then you unlocked Steaming Sauna, you would have no maximum hand size." / Dollmaker's Shop // Porcelain Gallery ruling (2024-09-20): "Any power- or toughness-setting effects that start to apply to a creature you control after Porcelain Gallery is unlocked will overwrite this effect on that creature."
- Question: Unlocking a door gives the permanent its half's rules text, but neither the permanent nor any effect gets a new timestamp under 613.7 (613.7d-k don't list unlocking, and no CR rule mentions timestamps for Rooms). Read literally, 613.7a gives the door's static abilities the Room's own timestamp from when it entered: the door's ability is "on" the Room, and the only effect involved, 709.5's gate, is a static ability of the Room itself (the Room's timestamp) that removes text rather than creating it; unlocking gives a designation (709.5e/f), not a continuous effect, so 613.7b doesn't apply either. Two rulings from the Rooms' own release say the door's effects date from the unlocking. In which order do that half's static effects apply relative to effects that began between the Room entering and the door being unlocked?
- Decision: Decided by the user, Nov 5. A knowing deviation from literal 613.7a in favour of the two rulings: the static abilities of a half unlocked after the permanent entered have the later of the permanent's timestamp and the moment that door was (last) unlocked, in layers and in rule-modifying effects alike. Only the unlocked door is re-timestamped, not the whole permanent. A door locked (709.5g) and unlocked again is timestamped from the new unlocking (no ruling covers this; consistent with the rulings). A half that was cast (and so entered unlocked, 709.5d) uses the permanent's timestamp, and if the permanent itself later gets a newer timestamp (613.7f), the newer one wins. Scope: this applies to Rooms only; Classes (716.2a) and levelers (711.2a) keep the permanent's timestamp for their gated abilities, as the leveler ruling says.
- Alternatives: (1) The literal 613.7a reading: the permanent's own timestamp for both halves, so an effect that began between the Room entering and the unlocking applies after the door's effect, the opposite of both rulings. The closest official precedent for it is the leveler ruling (2010-06-15): "The timestamp of each level symbol's ability is the same as the timestamp of the leveler itself, regardless of when the most recent level counter was put on it." A leveler's gate ("As long as this creature has at least N1 level counters on it ... it has ...", 711.2a) has the same structure as a Room's, but it works in layers 6 and 7b on top of unchanged printed characteristics, while 709.5's gate works on copiable values (name, mana cost, rules text), like face up/down, transform and merge, which all have timestamp rules. (2) Re-timestamp the whole permanent on unlocking (613.7f-style): no ruling asks for it, and it differs from the per-door reading only for Dazzling Theater // Prop Room (the only Room with static abilities on both doors), where the difference isn't observable in practice. (3) A narrow reading of the rulings (their examples assume the Room entered after Null Profusion, or Porcelain Gallery was cast): it would remove the conflict, but it makes the rulings' chosen wording pointless ("you unlocked Steaming Sauna" contrasted with "Null Profusion entered"; Porcelain Gallery's "after ... is unlocked" replaces the usual setting-ruling template's "enters", and the 4WW Porcelain Gallery and 3UU Steaming Sauna are the doors normally unlocked later, after casting the cheap door), so it is not adopted.
- Why: Conclusion D (unresolved, leaning C), confidence medium; recommendation: keep following the rulings (the engine's behaviour, status quo). Decided by the user on Nov 5: follow the rulings, so an unlocked door's abilities are timestamped from the unlocking; the kind stays a deviation from a literal reading of 613.7a. For the rulings: two rulings from the same release (2024-09-20, Duskmourn, the release that introduced 709.5) both assume the unlock time, per door; the CR re-timestamps every other in-place change of a permanent's copiable characteristics (613.7f face up/down, 613.7g transform/convert, 730.2a merge), so unlocking reads as an omission from that list; players expect "the thing that turned on later wins". Against: 613.7a is explicit and gives a determinate answer for the conflicting case (the Room enters, then Null Profusion enters, then the door is unlocked); the leveler ruling (2010-06-15) applies 613.7a literally to an analogous gated static ability; and the CR in the repo (2026-09-25) has had two years of updates without adding an unlock timestamp rule. Not B: the rulings and 709.5 came out together, and nothing in the CR has changed since. Not verified: whether the Duskmourn Comprehensive Rules update bulletin or a judge article addresses this (magic.wizards.com and www.cranial-insertion.com, whose article 4292 of 2024-09-23 is a Room Q&A, are outside this session's allowed network hosts; WebSearch found no judge article, bulletin or Q&A on unlock timestamps, 2026-11-04). Following the literal CR instead would mean dropping the `unlocked_at` door timestamps in layers.rs (both call sites) and rewriting the two tests.
- Affects: Rooms whose static abilities overlap with other effects in a layer or in rule-modifying effects: Secret Arcade (layer 4, adding types), Lecture Hall (layer 6, hexproof against ability-removing effects), Greenhouse (layer 6, a mana ability grant), Porcelain Gallery (layer 7b), Steaming Sauna (maximum hand size, 613.11), Walk-In Closet and Dazzling Theater // Prop Room (permissions). Not replacement-effect doors such as Torture Pit (ordered by the affected player, 616), and not Classes or levelers.
- Code: `crates/mtg-engine/src/rooms.rs` (`RoomState::unlocked_at`, `door_timestamp`); `crates/mtg-engine/src/layers.rs` (`static_timestamp`, `collect_statics`, `compute_player_effects`).
- Tests: `tests/rulings/r_p010_misc.rs` (`steaming_sauna_and_null_profusion_apply_in_timestamp_order`); `tests/rulings/r_p010_layers.rs` (`porcelain_gallery_unlocked_later_sets_base_pt_after_earlier_effects`: a layer-7b door, and a door locked and unlocked again).

## star-without-defining-ability-is-zero: A printed * whose power- or toughness-defining ability is gone counts as 0, so Tarmogoyf's */1+* is 0/1
- Kind: interpretation
- Status: provisional
- Rules: 208.2 "Rather than a fixed number, some creature cards have power and/or toughness that includes a star (*)." / 208.2a "The card may have a characteristic-defining ability that sets its power and/or toughness according to some stated condition. (See rule 604.3.) ... This ability functions everywhere, even outside the game. If the ability needs to use a number that can’t be determined, including inside a calculation, use 0 instead of that number." / 208.5 "If a creature somehow has no value for its power, its power is 0. The same is true for toughness." / 613.1f "Layer 6: Ability-adding effects, keyword counters, ability-removing effects, and effects that say an object can’t have an ability are applied." / 613.4a "Layer 7a: Effects from characteristic-defining abilities that define power and/or toughness are applied. See rule 604.3."
- Question: Dress Down ("Creatures lose all abilities") removes Tarmogoyf's power- and toughness-defining ability in layer 6, so nothing applies in layer 7a and the printed */1+* is all that's left. 208.2a says what to do when the ability can't determine a number, and 208.5 what a creature with no value at all has, but neither says what a printed "1+*" is when the defining ability no longer exists: is the * zero (toughness 1) or is the whole toughness undetermined (toughness 0, and the creature dies)?
- Decision: The * is 0 (provisional). A printed power or toughness with a star and no defining ability is its numeric part: Tarmogoyf under Dress Down is 0/1 and survives; Nightmare (*/*) is 0/0 and dies. The same values are used wherever the defining ability doesn't apply.
- Alternatives: Read 208.5 as covering the whole characteristic: "1+*" has no value, so the toughness is 0 and Tarmogoyf dies under Dress Down.
- Why: 208.2a treats an undeterminable number inside a calculation as 0, and the printed "1+*" is such a calculation with the * undetermined; this is also the generally given answer for Dress Down and Tarmogoyf. No Scryfall ruling on Dress Down, Tarmogoyf or Humility addresses it, and the CR doesn't say it in so many words, so a judge could rule the other way.
- Affects: Creatures printed with a star in a sum ("1+*", "2+*", "*+1") whose defining ability is removed (Dress Down, Humility doesn't show it since it sets base 1/1, Turn to Frog and Ovinize set the values): Tarmogoyf, Angry Mob (2+*/2+*), Dungrove Elder (*/*) is unaffected (0/0 either way). Plain */* creatures are 0/0 under both readings.
- Code: `crates/mtg-engine/src/card.rs` (`parse_pt`: the numeric part of a starred value, `star_power`/`star_toughness`); `crates/mtg-engine/src/layers.rs` (layer 7a applies defining abilities only while the object has them).
- Tests: `tests/cr/r613_audit_cda_counters.rs` (`losing_all_abilities_removes_a_defining_ability_so_a_star_counts_as_zero`).
